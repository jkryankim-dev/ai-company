# 비공개 테스트 통과 플레이북 (Beads Sort)

## 현재 위치
```
✅ 비공개 테스트 버전 게시
✅ 12명 이상 옵트인 — 33명 완료 (2026-08-19 대표 확인, 콘솔 옵트인 기준)
▶ 12명 대상 14일 이상 실행 — 시계 가동 중 (시작일 D0는 대표 확인 필요)
```
14일 시계는 **12명이 옵트인을 완료한 시점부터** 돈다. 12명 요건은 이미 충족(옵트인 33명)했고 시계는 가동 중이다.
옵트인 단계는 끝났다. 남은 관문은 **14일간의 실행 기록**이다 — 이게 다른 모든 작업보다 앞선다.

## 반드시 알아야 할 것 — 숫자가 아니라 참여도다
구글은 설치 수가 아니라 **실제 사용**을 본다. 프로덕션 접근이 거절되는 가장 흔한 이유가
"테스터가 설치만 하고 다시 열지 않음"이다. 12명은 머릿수 요건이 아니라 참여 요건이다.

거절 사유로 알려진 것들:
1. 테스터가 설치 후 앱을 다시 열지 않음
2. 상호 테스트 그룹 참가자가 초반 설치 후 이탈 — 인원은 유지되나 기록이 빈약
3. 프로덕션 신청서 10문항에 짧고 성의 없는 답변 (각 300자 가능한데 30자만 씀)
4. 사전 출시 보고서(Pre-launch report)의 크래시를 방치
5. 테스터 기기·지역·안드로이드 버전이 전부 동일 — 인위적으로 보임
6. 14일 딱 채우고 즉시 신청 — 형식은 맞지만 기록이 얇음
7. 개인정보처리방침 누락, 데이터 안전 미완성 등 등록정보 미비

## 목표 설정
- 모집 인원 **15~16명** (12명은 최소값. 이탈 대비 여유분)
- 기기·안드로이드 버전을 일부러 섞을 것
- 14일간 **매일은 아니어도 주 3~4회** 실행하는 사람으로

## 옵트인이 실패하는 이유 (이탈 대체 모집 시 참고 — 옵트인은 완료 상태)
테스터가 "하겠다"고 답해도 실제 옵트인까지 가는 비율이 낮다. 전형적인 실패:
- 나에게 알려준 계정과 **다른 구글 계정**으로 플레이 스토어에 로그인되어 있음
- 옵트인 링크를 눌렀지만 "테스터가 되기" 버튼을 안 누름
- 옵트인 후 스토어 반영까지 시간이 걸리는데 안 뜬다고 포기
- 웹이 아닌 앱에서 링크를 열어 페이지가 다르게 보임

→ 그래서 모집 문구에 **옵트인 3단계 안내를 그림처럼 명확하게** 넣어야 한다. 이게 전환율을 좌우한다.

## 지금부터 기록해야 할 것 (중요)
프로덕션 신청서 10문항은 "어떤 버그를 발견했고 어떻게 고쳤는지, 빌드 번호는 무엇인지,
테스터를 어떻게 모집했는지"를 구체적으로 묻는다. **14일이 지난 뒤에 기억으로 쓸 수 없다.**
오늘부터 테스트 일지를 쌓는다.

`projects/beads-sort/test-journal.md` 에 다음을 누적한다:
- 날짜 / 빌드 번호 / 테스터가 보고한 문제 / 원인 / 수정 커밋 / 재배포 여부
- 옵트인 현황 변화 (몇 명 → 몇 명)
- 모집 채널별 결과

## 직원 분담
- **서카피**: 모집 문구(지인용/커뮤니티용 2안), 옵트인 3단계 안내문, 14일간 쓸 리마인드 메시지 3종
- **오운영**: 테스터 추적표 양식(이름·계정·옵트인 일자·최근 실행), 이탈 감지 규칙
- **이빌드**: 사전 출시 보고서 크래시 대응, 데이터 안전 양식 답안 초안
- **박빌드**: 릴리즈 빌드·서명 검증, targetSdk 요건 확인
- **김기획**: 프로덕션 신청 10문항 답안 초안 (테스트 일지 기반, 14일 후 작성)
- **최감사**: 신청 직전 전수 점검

## 대표만 할 수 있는 것
테스터 모집과 실제 연락, 플레이 콘솔의 모든 제출 행위. 직원은 문구와 체크리스트까지만 만든다.
