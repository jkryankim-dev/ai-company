# 운영 전략 — 테스터 참여율 14일 유지 (경영전략회의)

작성: 오운영 / 2026-08-19
근거: `closed-test-playbook.md`, `tester-tracker.md`, `recruit-kit.md`, `sprint-01.md`, `context.md` 직접 열독

## 전제
모집 완료·14일 시계 가동 중, 최단 신청 2026-09-01 전후 (context.md 2026-08-18 대표 확인). 구글이 보는 것은 머릿수가 아니라 **실행 기록의 두께**다 — 거절 사유 1·2·6번은 전부 참여 부족이다 (플레이북).

## 할 것
1. **일일 루틴(매일 아침 10분)**: 대표가 콘솔의 최근 실행일 값을 넣으면 → 오운영이 `tester-tracker.md` 갱신 + 활동 집계를 스탠드업에 1행 보고. 이 기록이 쌓여 신청서 10문항의 답이 된다 (sprint-01 목표 A).
2. **참여율 목표(제안)**: 최근 3일 내 실행 테스터 ≥ 10명 유지. 주 3~4회 페이스가 요건의 실체이므로 (플레이북) 3일이 페이스 붕괴 판정 단위다.
3. **리마인드 2트랙**: 정기(3·7·12일차 단체, recruit-kit §4 완성본) + 비정기(3일 미실행자 개별 DM). 문구는 초안만 만들고 **발송은 전부 대표 몫**.
4. **피드백 회신 루프**: 테스터 보고 문제를 저널에 기록 → 수정되면 "다음 버전 반영" 회신. 참여 보상이자 재배포 기록 축적(신청서 근거).
5. **마무리 장치**: 13일차까지 기록 유지. 14일 딱 채우고 즉시 신청은 거절 사유 6번 (플레이북).
