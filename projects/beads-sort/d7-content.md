## 1. A안 — 숫자 리드형 (통과율을 첫 문장으로)

### 제목 2안
- A1. 통과율 〔N〕% 스테이지는 이렇게 만들었습니다 — 1인 개발 후기
- A2. 난이도를 감이 아니라 시뮬레이션으로 정하는 1인 개발

### 본문
```
〔스테이지〕 스테이지의 통과율은 〔N〕%입니다.

이 숫자는 출시 전부터 알고 있었습니다. 감이 아니라 시뮬레이션이 재 줬기 때문입니다.

Beads Sort는 혼자서 만든 구슬 정렬 퍼즐입니다. 구슬을 색별로 옮겨 담는 단순한 규칙에, 되돌리기 무제한·목숨 없음·시간 제한 없음을 얹었습니다 — 실수해도 되돌리면 되는 부담 없는 퍼즐입니다.

혼자 만드니 생기는 고민이 하나 있었습니다. "이 스테이지, 처음 접하는 사람이 깰 수 있을까?" — 이 질문에 대답해 줄 동료가 없습니다. 그래서 각 스테이지를 시뮬레이션으로 반복 풀이해 통과율을 계산하고, 그 숫자를 보고 스테이지 난이도를 조정했습니다.

통과율 숫자를 공개하는 정렬 퍼즐은 저가 아는 한 이 게임뿐입니다. 숫자가 있으면 자랑이 아니라 조정의 근거가 됩니다 — 어려운 스테이지는 일부러 어렵게 둔 것이고, 거기서 멈춘 사람이 많으면 다음 버전에서 난이도 곡선을 다시 맞춥니다.

게임은 무료입니다. 안드로이드: 〔스토어 링크〕

어떤 스테이지에서 막혔는지 댓글로 남겨 주세요 — 해당 스테이지의 통과율 숫자를 보여 드리고, 다음 조정에 직접 반영합니다.
```

## 2. B안 — 서사형 (문제 리드)

### 제목 2안
- B1. 혼자 퍼즐 게임을 만들 때 가장 어려운 문제
- B2. 출시 전에 '너무 어려운 스테이지'를 찾는 법

### 본문
```
혼자 게임을 만들면 생기는 가장 큰 문제는 기능이 아니라 판단입니다.

"이 스테이지, 처음 사람이 깰 수 있을까?" — 옆에서 대답해 줄 동료가 없습니다. 이탈률은 출시 후에야 데이터로 들어옵니다. 출시 전의 개발자는 대개 감으로 스테이지를 배치합니다.

저는 감을 믿는 대신 시뮬레이션을 돌렸습니다. 각 스테이지를 반복해서 풀어 보게 해 통과율을 계산하고, 그 숫자를 보고 스테이지 순서와 난이도를 정했습니다.

시뮬레이션이 완벽하다고 생각하지 않습니다. 사람의 지루함이나 인내까지는 재지 못합니다. 다만 "어려운 것 같다"는 느낌보다 "통과율 〔N〕%"라는 숫자가 조정할 만한 근거라는 건 분명합니다.

게임 소개: Beads Sort — 구슬을 색별로 옮겨 담는 정렬 퍼즐. 되돌리기 무제한·목숨 없음·오프라인 가능·무료.
다운로드: 〔스토어 링크〕

혹시 특정 스테이지에서 막혔다면 댓글로 남겨 주세요. 통과율 숫자를 보여 드리고 다음 조정에 반영합니다.
```

## 두 안의 차이와 추천
- A는 고유 소재(통과율 숫자)를 첫 문장에 놓는다 — 스크롤 지나가는 숫자가 시선을 잡고, "통과율"이 이 게임만 쓸 수 있는 표현이라는 전략(틈새 3, strategy-marketing.md:10)과 직결된다. 숫자를 기입하기 전엔 첫 문장이 비어 있어 발행 전 값 확인이 필수다.
- B는 '혼자 만드는 사람의 판단 문제'라는 보편 서사로 시작한다 — 개발·인디 게임 관심층 커뮤니티에서 공감 기반 반응을 노린다. 숫자 의존도가 낮아 플레이스홀더 리스크가 작다.
- **추천 A** — 전략이 지정한 소재의 핵심이 통과율 숫자 공개고, D-0 출시글이 이미 기능 소개형이었으므로 D+7은 숫자 리드로 차별화된다. 숫자 확보가 늦어지면 B로 대체 발행해도 구조상 무리가 없다.
