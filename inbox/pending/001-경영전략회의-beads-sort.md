# 경영전략회의 소집 — Beads Sort 성공 전략

대표 지시. 부서장 전원이 참여하는 전략회의를 소집한다.
안건은 하나다: **Beads Sort 를 성공한 앱으로 만들기 위해 각 부서는 무엇을 할 것인가.**

## 진행 방식 (한실장)
아래 여섯 명 전원에게 위임하라. 각자 자기 부서 관점의 전략 보고서를 제출하게 하라.
전원 위임이 원칙이다 — 이 회의에서 빠지는 부서는 없다.

## 부서장별 요구 사항 (각자 15줄 이내, 관련 파일을 실제로 읽고 쓸 것)
- pm: 비공개 테스트 2주 → 프로덕션 → 출시 후 4주까지의 로드맵. 단계별 목표와 가장 큰 리스크 1개.
- dev_1: 기술 관점 — 지금 코드에서 성공을 가로막을 수 있는 것 3가지 (안정성·성능·정책). 근거는 실제 코드/설정.
- dev_2: 심사 관점 — 프로덕션 심사에서 떨어질 수 있는 지점 전수 점검. 데이터 안전·권한·광고 SDK 기준.
- marketing: 성장 관점 — 이 장르(워터 소트 퍼즐)에서 우리가 이길 틈새. 스토어 노출 전략과 출시 주 콘텐츠 계획.
- ops: 운영 관점 — 테스터 참여율을 14일간 유지할 방법. 이탈 신호와 대응 루틴.
- analyst: 지표 관점 — "성공"의 정의. 출시 후 무엇을 몇 이상이면 성공인지 숫자로. 측정 방법 포함.

## 산출물
1. 각 부서장 보고서 → 자기 채널에 게시
2. 한실장: 전 보고서를 종합해 **전략 결정 초안 3개**(할 것)와 **버릴 것 1개**를 대표실에 게시.
   충돌하는 주장이 있으면 숨기지 말고 드러내라.
3. 대표 승인이 필요한 항목은 별도 표기.

이 결과는 sprint-01.md 와 함께 이번 2주의 실행 기준이 된다.
