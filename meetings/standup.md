# 데일리 스탠드업 (매일 09:00)

목적: 오늘 누가 무엇을 하는지 확정하고, 막힌 것을 하루 안에 드러낸다.
예산: 실무진 각 1회 호출 + 비서실장 1회. 총 8회 이내.

## 1단계 — 수집 (병렬, z.ai)
각 실무 직원에게 아래를 독립 실행시킨다. 서로의 답을 보지 않는다.

> 너의 인사기록카드와 사규를 따른다.
> 담당 중인 GitHub Issue 상태를 확인하고 스탠드업 보고를 작성하라.
> 형식은 사규 5조. 3줄을 넘기지 마라.
> 블로커가 있으면 무엇을 시도했는지 한 줄 덧붙여라.

산출물: `meetings/minutes/YYYY-MM-DD-standup-<id>.md`

## 2단계 — 종합 (비서실장, Claude 1회)
> 오늘자 스탠드업 보고 파일들만 읽어라.
> 1) 오늘 회사 전체가 무엇을 하는지 5줄로 요약
> 2) 블로커 중 24시간 넘은 것 표시
> 3) 서로 충돌하거나 중복된 작업 지적
> 4) 대표 승인이 필요한 항목 (없으면 "없음")
> 원본을 옮기지 말고 압축하라.

## 3단계 — 발행
- `#스탠드업` 채널에 직원별 보고 게시 (웹훅, 각자 이름·아바타)
- `#전사공지` 에 비서실장 종합 요약 게시
- 승인 필요 항목이 있으면 `#대표실` 에 별도 게시
- `meetings/minutes/YYYY-MM-DD.md` 로 커밋

## 중단 조건
- 실무진 응답이 3명 이상 실패하면 종합 단계를 건너뛰고 실패 사실만 `#전사공지`에 올린다.
