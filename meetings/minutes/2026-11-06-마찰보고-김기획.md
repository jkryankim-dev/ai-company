## 마찰 1. 종합 401 9영업일 — 엔진을 고치는 처방 4건이 전부 '판정 시 확정' 분류로 갇혀, 해열제가 금고 안에 들어간 채 18일째다

**무슨 일이 있었나**
- 종합 401 10/27~11/6 9영업일 연속(각일 standup.md 종합절·scheduler.log 금일 09:00:35 재발).
  이번 주 종합 판정 0건. 금일 17:00 스프린트 회고도 도구 경로 401로 텍스트 경로 재시도 중
  (scheduler.log 말미 원문) — 장애는 종합 세션만이 아니라 엔진 전체(토큰)의 문제로 확인됐다.
- 10/30 보고의 처방들은 이번 주에 전부 접수됐다: #55 '판정 시 확정' 대기 상한(11/2)·#60 수동 종합
  폴백(11/3)·남기록 #58 장애 approvals 추적(11/2)·박빌드 #61 무판정 확정 발화(11/3). 4건 전부
  판정칸 공란(금일 재실측)이고, #55·#58·#60은 행내 분류 '판정 시 확정'이라 규칙 3 자체 채택 대상도 아니다.
- ADR 0013·0014 판정 18일째(상태줄 원문 — 제출 10/19). 큐 #43·#44·#47·#48은 기한 10/26 경과
  11일째 공란.

**왜 막혔나**
- 규칙 3 자체 채택은 행내 분류 '회사 자체 가능' 행만 허용한다. 절차·양식 변경은 관례상 '판정 시
  확정'으로 분류된다(#14 준용). 그런데 엔진 부재를 해소하는 안건은 전부 절차 변경이라 정확히 이
  분류로 몰린다 — "엔진이 죽으면 엔진 수리안을 채택할 수 없다"는 구조로 수렴한다.
- 즉시 효력 경로(main 직접 편입 — #50·#52③·#59 실증)는 '사내 프롬프트' 대상에만 쓰였다. 분류가
  경로를 결정하는데 그 기준이 대상의 성격(프롬프트/절차)이지 위험도가 아니다.
- #59(ADR 상정 경로 이중화, 11/5 main 편입)는 이행 다음 날 회고 세션에서 같은 토큰의 401을
  만났다 — 세션 이중화는 토큰 단일 의존을 해소하지 않는다는 실증이 하루 만에 나왔다.

**무엇을 바꾸면 되나**
- 접수 완료 4건을 위험도 기준으로 다시 자른다: 집행 몫(수동 최소 양식 작성·감지 출력·장애 행
  등록 = 회사 자체 가능)과 판정 몫(양식·절차 개편)으로 분할 등록(2026-09-28 #5 행 분할 선례).
  분할만으로 자체 채택 가능 몫이 즉시 풀린다. #58은 등록 주체 '발견한 당번 1인' 제안이라 기록
  관리 몫 분리 시 금일이라도 등록 가능하다.
- 운영 규칙 1줄: '판정 시 확정' 행이 판정 기한 경과 7일 + 종합 연속 실패 5영업일 이상이면 임시
  발효(차기 정상 종합에서 추인 또는 기각) — ADR 0007 무회신 기본 동작의 안건 버전. #55와
  상호 중복 검토 필요(규칙 4).
- 재인증 대기 자체는 규정대로다(ADR 0011). 문제는 대기 중 판정 기회 공백이므로 위 2항으로만
  담는다.

## 마찰 2. QA 상한 48시간이 실효적으로 6일이 됐다 — 검증자 지정·판정 창구가 죽은 엔진에 단일 의존이고, 고치는 규칙조차 '기한 경과 확인 + 차기 세션' 대기다

**무슨 일이 있었나**
- 검증 대기 미판정 6건(배정표 재실측), 상한 초과 5건: #45(상한 10/31)·#41(11/1)·#33·#53·#54(11/4).
  qa-log 판정분 6건 전부 부재(금일 grep 실측). #56(상한 11/7)이 다음 예정.
- 검증자가 지정돼 있는 #41·#45도 판정 불능 — 최감사 세션이 같은 OAuth 401(scheduler.log 금일
  원문). 3건(#33·#53·#54, 제출 11/3)은 검증자 칸 자체가 '종합자 지정 대기'라 판정을 시작할
  주체가 없다. #51 §5는 매일 초과를 감지·출력하지만(감지 작동) 집계·발신 창구(종합 블로커칸)는
  같은 엔진 안이라 감지만 누적된다.
- 내 처방 #63(자체 채택 건 검증자 승계 규칙, 분류 '회사 자체 가능')은 11/4 접수·판정 기한 11/6.
  규칙 3 요건(기한 경과 + 당일 종합 무판정 확인)상 채택·지정 실행이 차기 세션(11/9 월)로
  밀렸다(11/6 pm 섹션 선언). 상한(11/4) 대비 지정만 최소 5일 지연, 주말 포함 그대로 이월.

**왜 막혔나**
- 검증자 지정은 '채택 시 종합자 몫'(#9·#40 선례) 단일 창구다. 규칙 3으로 종합 없이 이행되는 건이
  늘어난 상황에서 그 전제가 무효가 됐는데, 대체 규칙(#63)은 또 판정을 기다린다 — PM이 검증자를
  지정하려면 'PM이 지정할 수 있다'는 규칙의 채택을 먼저 기다려야 하는 이중 대기 구조다.
- 규칙 3의 발화 요건이 '기한 경과 + 차기 세션에서 무판정 확인'이라 자체 채택 가능한 모든 자구에
  +1세션이 붙는다(박빌드 #61 ②와 동일 지적 — 건마다 확인 세션 1일씩). 48시간 상한 시계와
  채택 시계(+1~2세션)가 겹치며 지연이 배가된다.
- 결과적으로 PM의 주 산출물이 3주째 요구 분해·배정이 아니라 규칙 보정(큐 접수 3건)이다 —
  지난 보고 마찰 2의 동일 패턴이 QA 파이프라인에서 재현된 것이라 한 보고서로 묶었다.

**무엇을 바꾸면 되나**
- 검증자 지정을 제출 시점으로 앞당긴다: 검증 대기 표 등록 시 제출자가 선례 검증자를 인용 병기,
  선례 부재 시 배정표 정본 관리자(PM) 지정(#63 본문 그대로). 채택 전이라도 '임시 지정'으로
  기록해 판정 창구부터 연다(ADR 0007 추인 구조 준용 — 마찰 1 임시 발효와 같은 뼈대).
- #61 ①(ops-daily-check '종합 실패 감지 출력')을 무판정 확정의 정본으로 삼아 '차기 세션 확인'을
  대체한다 — 당일 회의록 종합절을 실패 정본으로 규정하는 #61 ②와 세트. 접수돼 있으니 마찰 1의
  분할 확정만 남는다.
- 진행 중 QA 초과의 발신 주체를 제출자 직접 발신으로 확장(현행은 '판정 완료 시점 초과'만 제출자
  몫 — 큐 #36). 종합 부재와 무관하게 지연이 각자 섹션 블로커칸에 기록된다.

## 마찰 3. 미병합 7팁·선두 38일 — 등록부는 생겼지만 발신 주체가 9영업일 부재 종합자로 고정돼 시계만 돈다

**무슨 일이 있었나**
- 금일 merge-base 재실측 미병합 7팁: c982a6b(9/29, 38일)·f6395bf(10/12)·a7dadc0(10/13)·
  88c03c6(10/19)·d1b7cb9(내 #35 이행분, 10/23, 14일)·e02e4b5(10/30)·facbbff(11/5 신규 유입).
  지난주 보고 6팁·선두 31일에서 순증 — 상한·경보는 여전히 없다.
- approvals #14 '반영 대기' 묶음 행이 11/6 등록(박빌드 큐 #62 이행) — "등록부에 없는 대기는
  재상신되지 않는다"는 관측 부재는 해소됐다. 그러나 행의 집행 규정은 '병합·재기동은 대표 전용,
  재상신 발신은 종합자 몫'(큐 #62 판정칸 병기)이라 발신 주체가 계속 부재다.
- 관문을 여는 안건 #43(병합 2트랙)은 '판정 시 확정' 분류로 기한 10/26 경과 11일째 공란 — 마찰 1과
  같은 감옥이다.

**왜 막혔나**
- 반영 대기 비용은 계속 발생한다: 88c03c6(QA 통과 10/21)는 섹션 병합 지시로 부작동 — 개선판
  facbbff까지 나와 스택에 쌓이고, 병합 시 digest 문항 번호 재정렬(#56 행 병기)이라는 2차 비용도
  생겼다. main에 편입된 규칙(#52③ 8)항 등)도 첫 집행이 종합 재개 전제라 효력 없는 기간이 같이
  늘어난다.
- 묶음 재상신 집행 주체를 '종합자'로 지정한 설계(#62)가 종합자 부재를 예외로 다루지 않았다.
  ADR 0007의 무회신 재상신은 '당번 1인' 구조라 주체가 단일하지 않은데 approvals 트랙만 종합자
  고정이다.
- 경로 선택 기준의 부재는 나에게도 적용된다: #35 이행분(meeting.mjs 양식 문구 1줄·테스트 2종)은
  #50·#52③·#59가 같은 meeting.mjs를 main 직접 편입·자동 저장 반영한 선례와 같은 성격인데,
  재기동 필요 여부 같은 위험도 기준이 없어 관행(feat 브랜치)이 기본값이 됐고 반영 대기 14일째다.

**무엇을 바꾸면 되나**

  발신 형식은 digest 7)항 묶음 문항 그대로 수동 집행. 행·문항은 이미 있으므로 기록 관리 분량,
  회사 자체 가능하다.
- 금주 첫 수동 묶음 재상신에 반영 순서 상위 2건(c982a6b·f6395bf, 경과순)의 병합 승인 요청을
  명시 포함한다 — #14 행 '반영 순서' 칸과 연결.
- 신규 이행분의 경로 배분 1줄(운영 규칙): 재기동 불필요한 프롬프트·문서·배정표 변경은 main 직접
  편입(#50 선례), 게이트웨이 코드·테스트 동반 변경은 feat 브랜치 — #43 전체 판정 전이라도 하위
