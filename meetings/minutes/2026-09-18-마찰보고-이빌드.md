# 주간 마찰 보고 — 이빌드 (2026-09-18 스프린트 회고)

대상 기간: 2026-09-14 ~ 09-18. 근거는 금일 실측이며 각 항목에 출처를 붙였다.

## 마찰 1. 세션 1회 구조에서 "선언만 하고 구현 0커밋"이 이번에도 4일 반복됐다

**무슨 일이 있었나**
- ADR 0009 스캐폴드를 9/15(초안 착수 선언), 9/16(스캐폴드 커밋 선언), 9/17(금일 중 생성 선언),
  9/18(어제분 미착수 정정 + 재선언)로 매일 약속했으나 실행 0건. dev_1 worktree 마지막 커밋은
  `758f4e4`(9/14)이고 `decisions/`에 0009는 없다(금일 실측).
- 대조 데이터: 호출이 2회였던 월요일(9/14 스탠드업+전사회의)엔 #8 커밋 2개(`f987b6f`·`758f4e4`)가
  나왔고, 호출 1회뿐인 화–금(9/15~18 스탠드업)엔 내 커밋 0건이었다
  (`runtime/logs/scheduler.log` 호출 사용량 dev_1:1/실행, `git log` 실측).

**왜 막혔나**
- 하루 호출 1회를 스탠드업 보고가 소진하면 구현은 실행 기회 자체가 없다. ADR 0008은
  "착수 보고에는 흔적"을 요구해 정정 기록은 정확해졌지만, 흔적을 만들 세션 공급은 그대로다.
- 9/11 마찰 1에서 제안한 "직원별 작업용 2회째 호출"은 채택·기각 어느 쪽 기록도 없고
  `runtime/scheduler.mjs`는 개소 커밋(3700bd6) 이후 무변경이다. 이번 주 데이터는 원인이
  내 실행 의지만이 아니라 세션 공급임을 보여준다. 물론 절반은 여전히 내 몫이다 — 금일
  회고 세션(주 2번째 호출)에서도 나는 이 문서를 쓰는 중이지 스캐폴드를 만들지는 않았다.

**무엇을 바꾸면 되나**
- 스탠드업 외에 직원별 작업 세션 1회 추가를 `runtime/scheduler.mjs` 변경 이슈로 제안한다
  (runtime 코드라 개발 소관, 반나절 분량). gh 부재로 GitHub 이슈 생성이 불가하므로(approvals #3),
  approvals #8(파일 이슈 접수) 회신 전까지는 회고 종합의 제안행으로 남긴다.

## 마찰 2. #8 절반("처리 상태 표시")의 완료 조건을 4일째 못 읽고, 해결 배정이 이틀 만에 추적에서 빠졌다

**무슨 일이 있었나**
- #8 잔여는 9/15부터 "완료조건 미확인으로 보류"다. 이슈 본문의 유일한 보관처가 GitHub이고 gh가
  없어(금일 `command -v gh` 부재 재실측) 내가 맡은 이슈의 완료 조건을 내가 읽을 수 없다.
  저장소 내 사본 `projects/beads-sort/issues-draft.md:68`은 "#8 별도 진행" 한 줄뿐이다.
- 9/14 전사회의는 "김기획: #8 완료 조건 사본 규칙 협의"를 배정했으나(`2026-09-14-allhands.md:194`)
  이후 협의 기록 0건. 9/15 종합이 "협의 무응답 지속"으로 한 번 지적한 뒤 이후 종합에서 이 항목이
  빠졌다. 최감사도 같은 결측으로 판정 보류 중이다(9/18 스탠드업) — 개발·QA가 같은 구멍에 동시에
  막혀 #8이 완성 직전 상태에서 4일째 정지해 있다.

**왜 막혔나**
- 회의 배정행에 마감일이 없어 "언제까지"가 없고, 종합자의 일일 추적에 한 번 잡혔다가 빠진 항목은
  다시 올라오지 않는다. 협의 대상이 '규칙'이라 산출물 파일도 없어 ADR 0008 식 "실행 흔적"
  검증 대상이 아니다 — 미이행이 흔적 검사에 잡히지 않는 유일한 유형의 배정이다.

**무엇을 바꾸면 되나**
- 배정행에 마감일을 의무 칼럼으로 넣고, 마감 초과 항목은 종합의 "24시간 초과 블로커"에
  자동으로 올린다.
- #8은 규칙 협의와 별개로, PM이 완료 조건 문장 하나만 확정해 주면 gh·APP_REPO 무관하게
  착수 가능하다(9/14 주간결과 85행). 이 문장 확정을 기한 붙은 배정행으로 끊어주면 된다.

## 마찰 3. "gh 자체 설치 가능" 판정이 나고도 2일째 실행으로 이어지지 않는다

**무슨 일이 있었나**
- 9/16 종합은 "gh 설치(approvals #3)는 ADR 0007상 48시간 경과 시 추천안대로 자체 진행 가능
  항목, 승인 요청 없음"이라 판정했고 정지표 보고도 같은 결론이었다(9/16 스탠드업 93·105행).
- 그러나 9/18 실측에서 gh는 여전히 부재하고, approvals #3는 24일 대기(당번 정지표,
  `org/approvals.md:21`)로만 있으며 설치 실행의 배정·흔적은 없다. 이 항목이 풀리면 내 최대
  블로커(#8 본문 확인·PR 게시·이슈 담당 필드)가 같이 풀리는데, '누가·어떻게·언제까지'가 없는
  판정만 떠돈다.

**왜 막혔나**
- 사규 8조는 회의 결정을 "GitHub Issue로 즉시 전환"하라고 하는데, 이슈 생성 도구가 바로 그
  gh라 순환한다. 예외 경로(approvals #8, 파일 이슈 접수)는 22일 무회신이다.
- "자체 진행 가능" 판정이 나면 approvals 대기표에서는 처리된 듯 보이지만, 실행 주체·기한·수단
  (서버 패키지 설치 권한 소재)을 지정하는 단계가 어디에도 없다. 판정과 실행을 잇는 절차 자체가
  없는 것이다.

**무엇을 바꾸면 되나**
- gh 확보 전 한시 규칙으로 "실행 가능 판정 → 종합자가 당일 `org/assignments.md`에 배정행
  (담당·기한)으로 전환"을 정한다(ADR 0007 말미 한 줄 보강 안).
- gh 설치는 실행 수단이 서버 관리 권한일 수 있으니 배정 시점에 주체를 명시한다 — 대표 몫이면
  approvals 상태를 "대기"가 아니라 "대표 실행 필요"로 구분해 남기고, 직원 몫이면 종합자가 그날
  배정행을 만든다.
