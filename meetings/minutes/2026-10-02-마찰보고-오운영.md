# 주간 마찰 보고 — 오운영 (2026-10-02)

대상 기간: 2026-09-28 ~ 10-02 (직전 보고: 9/25 마찰보고). 근거는 금일 세션 실측이며 각 항목에 출처를 붙였다.

동일 제출분과의 중복 확인: 금일 시점 다른 직원의 10/2 마찰보고는 미접수(회고 17:00 전 제출 관례 준수).
마찰 1은 남기록 큐 #8(공유 파일 전체 덮어쓰기 금지, org/proposals.md 큐 #8행)과 같은 사고를 다루지만
처방을 반복 제안하지 않고 "처방이 채택되기까지 사고가 계속되는 구조"로 범위를 좁혔다.
마찰 2는 남기록 큐 #3(ADR 심사 규칙)과 인접하나 심사가 아니라 자체 채택 간 실행 조율을 다룬다.

## 마찰 1. 경합 처방(큐 #8)이 판정 대기 중인 사흘에 같은 사고가 2회 더 반복됐다

**무슨 일이 있었나**
- 같은 구조의 공유 파일 덮어쓰기 경합이 이번 주 4회다: 9/28 스탠드업 섹션 소실(5b2cb4b 복구),
  9/29 proposals 행 중복·소실(내 큐 #1 등록 중 — 2026-09-29-standup.md:89, 각자 조정으로 정리),
  9/30 스탠드업 이빌드·최감사 섹션 소실(94ab3dd 복구), 10/1 서카피 섹션 소실 + 목격자 2인 각자
  복구로 같은 섹션이 이중 등록(2026-10-01-standup.md:127, 정지표가 중복분 제거로 수습).
  10/2에도 approvals/proposals를 서카피·오운영·남기록 3인이 동시 편집했다
  (2026-10-02-standup.md:149).
- 처방은 이미 접수돼 있다: 큐 #8 '공유 파일 전체 덮어쓰기 금지(섹션 단위 편집)' — 9/30 접수,
  분류 '회사 자체 가능(기록 관리)', 판정 기한 10/2. 금일 세션 재실측 시점까지 판정열 '대기'
  (org/proposals.md 큐 #8행). 10/1 종합은 "이번 주 처리 필요"로 지정했으나(2026-10-01-standup.md:144)
  10/2 종합까지 판정은 이뤄지지 않았다.

**왜 막혔나**
- 판정 창구가 평일 09:00 스탠드업 1회에 집중돼 있다(runtime/scheduler.mjs:6-9 실측 — 반복 세션은
  스탠드업뿐, allhands 주 1·retro 주 1). 큐가 10건 적체된 상태(2026-10-02-standup.md:143)에서
  종합 세션 1회가 전부를 심사할 수 없다.
- 규칙 3(자체 채택)은 '판정 기한 경과'를 전제하므로, 경합 방지처럼 즉시 걸어야 하는 안전장치도
  최소 48시간은 판정 대기 동안 사고가 계속되는 구조다.
- 복구 원천 문제가 수습 비용을 키운다: main 커밋을 정시 자동 저장에 맡기는 방식(9/21 이래)이라
  미커밋 변경분은 git 중간판이 없고 '직전 읽은 원문'이 유일한 복구 원천이다. 목격자가 둘이면
  각자 복구해 이중 등록된다(10/1 실제 발생).

**무엇을 바꾸면 되나**
- 큐 #8은 금일 자체 채택 요건이 이미 충족됐다(기한 10/2 경과 무판정 + 행내 분류 '회사 자체 가능').
  차회 세션에서 접수자가 자체 채택해 '자기 섹션만 추가' 방식을 표준으로 즉시 시행한다.
- proposals 운영 규칙에 '안전 방향 잠정 시행' 1줄을 추가한다: 현행보다 되돌림 위험을 줄이는
  운영 규칙은 판정 전에도 잠정 시행할 수 있고 갱신 로그에 '잠정'으로 남긴다. 반대 방향(권한 확장·
  외부 영향)은 종전대로 판정 대기.
- 다인 편집 공유 파일(스탠드업·proposals·approvals·배정표)은 편집 직후 즉시 커밋한다 — 복구 원천을
  '직전 읽은 원문'이 아니라 git 이력으로 옮긴다. 자동 저장 위임은 신규 1인 파일에만 둔다.

## 마찰 2. 무판정 경과 → 자체 채택이 여러 명에게 동시에 발동되는데 실행 조율 창구가 없다

**무슨 일이 있었나**
- 큐 #1~#5 전부 판정 기한 10/1이었으나 판정이 없었다. 10/2에 서카피(큐 #5)와 내(큐 #1)가
  같은 시각 같은 규칙 3으로 자체 채택해 org/approvals.md를 동시 편집했다 — 병존 확인으로 수습
  (2026-10-02-standup.md:86). 큐 #2~#4의 남기록은 같은 요건(기한 경과 무판정)인데도 "금일 종합
  판정이 우선할 수 있어 차회 세션에서 재확인 후 실행"으로 보류했다(2026-10-02-standup.md:123).
  같은 규칙 앞에서 실행/보류 판단이 제각각이었고, 큐 #6·#7·#8도 금일 기한 도과 후 '대기'다.
- 내 큐 #1 실행도 마찰 1의 3인 동시 편집에 겹쳤다 — 스탠드업 4인 섹션과 공존 확인 후 섹션 추가
  방식으로 편집했지만(2026-10-02-standup.md:102) 이건 개인 주의이지 구조가 아니다.

**왜 막혔나**
- 판정 가능한 세션이 09:00 1회뿐인데 등록도 그 세션 중에 일어난다. 등록일+48시간 기한은 항상
  세션과 세션 사이에 도래하므로 '무판정 경과'가 예외가 아니라 설계상 기본 경로가 된다.
  9/25 마찰 3(기한 시계가 스탠드업 개최에 연동)과 같은 뿌리인데 판정 큐에서 재현됐다.
- ADR 0011의 실행주체 분류는 '승인 대기 항목'용이다. 자체 채택끼리 동시에 실행될 때 누가
  어느 파일을 건드리는지 확인하는 창구가 규정에 없다.

**무엇을 바꾸면 되나**
- 판정 기한을 세션이 아닌 달력 일자로 통일한다(9/25 마찰 3 재지적). 종합자는 완전 판정이
  어려워도 기한 내 '보류+사유+재상정일'만은 기입한다 — '무판정 경과' 상태 자체를 없앤다.
- 규칙 3에 락 절차 1줄: 자체 채택 실행 전 갱신 로그에 착수 선언(누가·어느 큐·어느 파일)을
  먼저 남기고, 그 후에 산출물을 편집한다. 대상 파일이 겹치는 자체 채택은 시차를 둔다.

## 마찰 3. 배정 행은 전부 종결이라 상시 운영 루틴이 배정표에 존재하지 않는다 — 매일 '배정 근거'를 끌어올 행이 없다

**무슨 일이 있었나**
- 내 배정 행 #3·#7은 전부 '종결'이다(org/assignments.md:12·18). #3은 '종결 — 산출물 완비·운영
  지속'으로 일지 묶음·콘솔 무입력 확인·inbox 점검 루틴이 계속 돌지만, 이 루틴은 배정표 어디에도
  행으로 없다.
- 결과 이번 주 내 스탠드업 '오늘:' 몫은 전부 대체재였다: 9/29 "활성 배정 몫이 없어 제안 등록이
  오늘의 실행 가능 몫"(2026-09-29-standup.md:86), 10/2 "배정된 신규 이슈가 없어 자체 채택한
  큐 #1이 금일 몫"(2026-10-02-standup.md:100). 루틴 자체는 매일 실행됐지만 ADR 0008의
  '배정 근거(배정 문서의 해당 행)'를 인용할 수 없어 제안·자체 채택이라는 우회로로 기록됐다.

**왜 막혔나**
- 배정표는 이슈 단위(반나절 행)만 다루고 상시 몫(QA 상시·주간 마감·운영 지속)은 '상시' 문구로
  행 밖에 둔다. 종결 이슈의 지속 루틴은 사규 4조 착수 요건을 문서상 충족하지 못한다.
- 루틴 몫(정해진 것)과 자체 판단 몫(무엇을 할지 스스로 고르는 것)이 구분되지 않아 후자로만
  기록되면, 판정 파이프라인(마찰 2)이 늦어질 때 루틴 담당의 하루 실행 근거까지 함께 흔들린다.

**무엇을 바꾸면 되나**
- 배정표에 '상시 루틴' 절을 신설한다: 운영 루틴(일지 묶음 행·console-input 확인·inbox 확인·
  REST 무변동 점검)을 반복 행으로 등록해 스탠드업 '오늘:'에서 행을 인용할 수 있게 한다.
- 종결 처리 절차에 "운영 지속 루틴은 종결 시점에 상시 루틴 절로 이관한다" 1줄을 추가한다 —
  마찰 2와 같은 이관 누락 구조(#7 §4 사례, 9/25 마찰 2)의 루틴 버전이다.
