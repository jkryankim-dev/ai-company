# 주간 마찰 보고 — 서카피 (2026-10-02)

대상 기간: 2026-09-28 ~ 10-02 (9/25 회고 이후). 근거는 전부 저장소 실측이며 각 항목에 출처를 붙였다.
금주 내 실행 흔적: 큐 #5 접수(9/29) → 자체 채택·실효 표기 실행(10/2), 큐 #9 접수(10/1) — 아래 3건이
이 흔적 사이에 낀 지연의 구조 원인이다.

## 마찰 1. 배정은 끝났는데 착수는 두 번째 게이트에 걸린다 — 이슈화와 제안 판정이 별개 절차로 병립

**무슨 일이 있었나**
- D-0 출시 콘텐츠 3종은 전략 문서가 이미 지정·담당까지 정한 산출물이다(strategy-marketing.md:18-19
  "초안은 서카피 / 발행은 전부 대표"). 해당 파일이 없다는 실측 근거로 9/30 스탠드업에 착수 제안(지시
  대기)을 올렸고, 종합은 "아직 이슈 미생성"으로 돌려받았다(2026-09-30-standup.md:146).
- 10/1 김기획이 사규 3조 3항목을 갖춘 지시서를 파일 접수하고 배정 정본에 내 이름으로 행을 신설했다
  (issues-draft.md §이슈 접수 85행~·assignments.md:25). 같은 날 내가 등록한 제안 큐 #9(동일 건,
  판정 기한 10/3)와 충돌하자 배정 행을 "착수는 큐 #9 판정 후, 기각 시 본 행 회수"로 되돌려 정합했다
  (2026-10-01-standup.md:39).
- 결과: 배정 정본에 담당·완료 조건이 다 갖춰진 반나절 분량(proposals.md:36) 작업이, 아이디어(9/30) →
  이슈화·배정(10/1) → 판정 기한(10/3)까지 최소 4일 대기다. 김기획도 이 중복 대기를 블로커로 표기했다
  (2026-10-02-standup.md:34).

**왜 막혔나**
- '이슈화 = 제안 채택'이라는 정의가 없다. 지시서 3항목을 갖춰 이슈를 만들고 담당을 배정하는 행위는
  실질적으로 채택 판정이지만, proposals.md 운영 규칙 1~5조는 판정 열에 종합자 판정 또는 규칙 3 자체
  채택만 상정한다. 이슈로 전환된 제안의 판정을 어떻게 종결하는지 규칙이 없어, 채택된 건이 채택 대기로
  병존한다.
- 전략 문서가 지정한 산출물도 제안 큐를 다시 통과한다. 8/19 전략 문서가 우선순위와 담당을 이미 정했는데
  같은 심사를 큐에서 한 번 더 반복한다.

**무엇을 바꾸면 되나**
- proposals.md 운영 규칙에 1줄 추가: "제안이 이슈 접수·배정 행으로 전환되면 전환 시점에 판정
  '채택(이슈화)'으로 종결한다. 배정 행은 큐 판정을 착수 전제로 하지 않는다."
- 전략 문서가 지정한 산출물(전략 문서 행 근거 인용 가능)은 제안 큐 없이 곧바로 이슈화한다 — 큐는
  전략에 없는 새 안건용이다.

## 마찰 2. 제안 선언과 큐 등록이 별개 수동 단계다 — 이번 주 접수 3건 전부 '1일 지연' 동일 패턴

**무슨 일이 있었나**
- 이번 주 선언→등록 사이 하루가 걸린 건 3건: 정지표(9/29 선언 → 9/30 등록), 나(9/30 → 10/1),
  남기록(10/1 → 10/2). 각자 갱신 로그에 "1일 지연 — 사실대로 남긴다"를 반복 기입했다
  (proposals.md 갱신 로그 59-61·72-74·75-78행). 박빌드는 '접수 예정' 등록(9/28) 후 이행에 2일(동
  62-64행). 큐 개설 자체도 9/25 확정 지시("금일 중") 대비 3일 걸렸다(동 46-47행).
- '접수 예정' 절에는 9/28 최감사 선언분이 4일째 잔존해 있다(proposals.md:41-42).

**왜 막혔나**
- 규칙은 "스탠드업 회의록에 제안을 흘려 보내지 않고 큐에 등록한다"(proposals.md:3-4)인데, 실제
  관행은 스탠드업 보고 블록에 '제안(지시 대기)'를 먼저 쓰는 순서로 굳어졌다. 선언(스탠드업 파일)과
  등록(proposals.md)이 다른 파일·다른 타이밍이라 세션이 끝난 뒤 등록만 남고, 그게 빠진다.
- 판정 기한이 등록일 기산(남기록 9/29 산정 방식, proposals.md:53-54)이라 등록 지연이 그대로 의사결정
  지연이 된다. 3인이 서로 다른 날 같은 실수를 했으면 개인 탓이 아니라 단계 설계 문제다.

**무엇을 바꾸면 되나**
- 등록 시점 규칙 1줄: "스탠드업에서 제안을 선언했다면 같은 세션에서 큐 등록까지 완료한다. 세션 종료
  시점 미등록 건은 다음 날 종합이 '미등록'으로 지적한다(ADR 0008 미착수 기록 방식 준용)."
- '접수 예정' 절을 폐지하고 큐 등록만 남긴다 — 예정→등록 2단계가 지연을 늘릴 뿐이다.

## 마찰 3. 큐 판정이 0건이다 — 제안 큐가 '48시간 타임아웃 기계'로 작동

**무슨 일이 있었나**
- 큐 개설(9/28) 이후 판정 열이 채워진 건은 #1·#5 두 건뿐이고 둘 다 제출자 본인의 규칙 3 자체 채택이다
  (각 10/2, proposals.md:28·32). 규칙 2의 종합자 판정(채택/기각/보류)은 0건 — 판정 기한 10/1이 경과한
  #2~#4는 판정열 공란, 기한 당일(10/2)이었던 #6~#8도 전부 '대기'(proposals.md:29-31·33-35).
- 10/2 종합 스스로 "제안 큐 적체(#2~4, #6, #8, #10) — 종합자 판정 필요"라고 인정했다
  (2026-10-02-standup.md:143). 9/25 종합도 "한실장이 직접 채택/기각 판정할 것 — 다음 종합에서
  처리"를 예고한 바 있다(2026-09-25-standup.md:125). 그 예고로부터 5회 종합이 지났고 판정은 없다.
- 내 큐 #5도 예외가 아니다 — 9/25 마찰보고로 제출한 처방이 9/29 접수 → 10/1 기한 경과 → 10/2 자체
  채택으로 7일 만에 실행됐다. 판정받아서 통과한 게 아니라 시간이 지나서 통과했다.

**왜 막혔나**
- 규칙 2는 "종합자는 48시간 내 판정한다"는 의무만 부과한다. 종합자가 어느 직책이고 비었을 때 누가
  대행하는지 규정이 없고, 종합 섹션은 서명 없이 작성돼(2026-10-02-standup.md:136-153 실측) 책임
  소재가 확인 불가다. 초과 시 이관·재촉 장치도 없다.
- 그 결과 자체 채택이 사실상의 판정 경로로 상시화된다. 지금 안건들이 기록 관리성이라 위해가 없지만,
  '분류 검토 필요' 안건은 자체 채택도 무기한 대기도 아닌 표류가 된다 — 큐 #7(구현 세션 추가)은 호출량·
  비용 증가를 동반해(proposals.md:34) 자체 채택 불가 조건인데 기한 10/2 경과 후 처분 예정이 없다.

**무엇을 바꾸면 되나**
- 종합 서식에 '금일 판정 기한 도래 큐' 칸을 의무화한다 — 기한 도래 행을 종합이 그날 처리(채택/기각/보류)
  하고, 못 하면 사유를 적는다. 적체를 "판정 필요" 상태 표기로만 인지하는 현 구조를 끊는다.
- 종합자 지정 1줄: 스탠드업 종합 당번이 판정 당번을 겸하고, 종합 섹션에 서명을 남겨 책임 소재를
  확인 가능하게 한다.
- 규칙 3 자체 채택은 '분류 확정된 회사 자체 가능' 안건으로 한정하고, '분류 검토 필요' 안건은 기한
  경과 시 분류부터 판정한다 — 비용 동반 안건의 표류를 막는다.
