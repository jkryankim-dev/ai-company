## 마찰 1. QA 합격 산출물의 '제출'에 10일이 걸렸다 — 폴백 경로가 사후 처방 구조다

**무슨 일이 있었나**
- #5-스크립트: 9/29 완성(7b80e09, node --test 3/3) → 9/30 QA 통과(`projects/beads-sort/qa-log.md:38`) →
  제출 10/9(d4a0538, pr-5-verify-script.md). 완성부터 제출까지 10일.
- 폴백 경로(큐 #13) 신설에 걸린 단계: 10/2 마찰보고 처방 → 10/5 선언 → 10/6 큐 접수(1일 지연,
  갱신 로그 기재) → 48시간 기한 10/8 채택 → 10/9 세션 제출. 처방 인지부터 제출까지 7일.
- 같은 구조의 선례(approvals#8 이슈 파일 접수, 9/21 처리)가 이미 있었는데도 PR에는 자동
  준용되지 않아 안건을 새로 만들어야 했다.

**왜 막혔나**
- PR 게시 채널이 gh 쓰기 토큰(approvals#11, 대표 전용)에 단일 결합돼 있다.
- 대체 경로는 표준 목록에 없어 "제안(지시 대기)" 큐로만 신설 가능하고, 큐는 48시간 판정 기한 +
  종합 세션 주기 + 제출자 접수 세션까지 3단계 대기를 더한다.
- ADR 0011 "동일 구조 재평가는 반복하지 않는다" 규정은 승인 항목 실행에 적용되지만 경로
  신설에는 대응 규정이 없다.

**무엇을 바꾸면 되나**
- 대표 전용 자원을 전제하는 제출·게시 경로는 배정 시점에 파일 기반 폴백을 기본값으로 지시서에
  명시한다(기존 선례 자동 준용).
- proposals.md 운영 규칙에 '파일 접수 경로 표'(이슈·PR·배포 등)를 두어, 신규 창구마다 큐를
  거치지 않고 기존 양식을 준용하게 한다.

## 마찰 2. 이번 주 내 실행 흔적이 전부 기록 관리 몫 — 구현 커밋 0

**무슨 일이 있었나**

  2026-08-19 최초 상신, `org/approvals.md` #2행 대기)·gh 토큰(#11). 이번 주 실행 흔적은 큐

  보류·대표 상정 중이다(proposals.md #7행).

**무엇을 바꾸면 되나**

  몫 재정의' 대상으로 표시한다.
- 대표 전용 대기가 2주를 넘은 행은 종합자가 잔여 자체 가능 몫을 반나절 행으로 분리 등록한다
  (9/28 #5 행 분할 등록 선례의 제도화).

## 마찰 3. 판정 기한 48시간이 세션 주기와 어긋나고, 판정칸은 채택 직후에도 공백이었다

**무슨 일이 있었나**
- 큐 #13·#14: 10/6 09:06 접수 → 기한 10/8 09:06. 기한(09:06)이 세션 개시(09:00)보다 뒤라
  기한 도래일 세션에서는 규칙 3(자체 채택) 요건이 성립하지 않는다. 실제로 10/8 세션 전
  시점까지 "자체 채택 요건 미성립 — 종합 판정 대기"(10/8 스탠드업 내 섹션)였고, 종합이
  판정하지 않았다면 자체 채택은 기한+1세션(10/9)까지 밀렸을 것이다.
- 10/8 종합에서 6건(#13~#18)이 전원 채택됐으나 판정칸은 전건 공백이었다(10/9 스탠드업 내
  특이사항). 큐 #15(동일 세션 기입 1세트화)이 바로 그 세션에서 채택됐고 적용 대상도
  "10/8 판정분부터"였는데, 실제 기입은 10/9 제출자(박빌드·이빌드) 전사로 이뤄졌다.

**왜 막혔나**
- 기한 산식 '제출일+48시간'이 종합 세션 시각과 맞물려 경계에 걸린 안건은 대기가 세션 1회
  길어진다.
- 판정 정본(회의록)과 관리 칸(proposals.md 판정열)이 분리돼 있고, 종합 양식에 '판정열 기입
  완료' 확인 단계가 없어 1세트화 규칙 채택만으로 시행이 보장되지 않았다.

**무엇을 바꾸면 되나**
- 기한 산식을 세션 기준으로 재정의한다: '제출일+2 영업일 09:00 종합 개시 시점' 등 세션
  시각에 맞춘 계산.
- 종합 양식 '금일 판정' 절 끝에 "proposals.md 판정열 기입 완료(예/아니오)" 1행을 추가해
  1세트 완료를 종합자가 자체 확인하게 한다.
