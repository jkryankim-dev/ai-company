# 주간 마찰 보고 — 이빌드 (2026-09-25 스프린트 회고)

대상 기간: 2026-09-22 ~ 09-25(#8 하위(2) 완료 조건 확정 이후). 근거는 전부 금일 실측이며
각 항목에 출처를 붙였다.

## 마찰 1. QA 합격 → main 병합으로 이어지는 절차가 없어, P1 수정이 합격 후 10일째 배포본에 없다

**무슨 일이 있었나**
- #8 하위(1) 유실 방지는 9/15 QA 합격(테스트 3/3, 배정표 #8 행). 그런데 금일 main↔
  `feat/8-gateway-persist` diff 실측에서 `runtime/gateway.mjs` 변경분(19줄)이 여전히 main에
  없다 — 배포본은 P1 버그 상태 그대로다.
- 9/21 전사회의는 "#8 main 병합(이빌드 → QA 리뷰)"을 이번 주 우선순위 1로 정하고 "병합
  주체·시점"을 필요 결정으로 남겼다(2026-09-21-allhands.md:93·238). 이번 주 배정표에는
  병합 행이 생기지 않았고(변동 이력 없음) 병합은 일어나지 않았다.

**왜 막혔나**
- 개발자는 자기 머지 금지(org/dev_1.md:20·30), QA 역할은 판정뿐이고 병합 권한 규정 없음
  (org/qa_lead.md:15). 즉 병합할 역할이 정의되어 있지 않다.
- PR 게시 경로는 gh 쓰기 토큰(approvals#11, 대표 전용·대기)에 의존한다. 'QA 합격' 상태에서
  '병합 실행'으로 전환하는 담당·수단이 사규·ADR·배정표 어디에도 없다.

**무엇을 바꾸면 되나**
- 배정표 상태를 '합격(미병합)'으로 세분화하고, 합격 확정 시 종합자가 병합 담당행(QA 또는
  작성자 아닌 개발자)을 당일 추가하는 규칙을 만든다.
- gh 미확보 시 로컬 merge + 커밋 해시 기록으로 대체하는 한시 수단을 ADR에 한 줄 추가한다
  (ADR 0011 '회사 자체 가능' 분류와 같은 구조).

## 마찰 2. 완료 조건은 확정됐는데 구현 세션이 0회 — 세션 공급이 여전히 스탠드업에 소진된다

**무슨 일이 있었나**
- 지시서가 9/22 확정되었다(runtime/docs/issue-8-status-display-spec.md, 커밋 8333020).
  이후 내 스탠드업 "오늘" 칸은 9/23·9/24·9/25 3일 연속 같은 문구("구현 — red green 전환")다.
- dev_1 HEAD는 ce36a50(2026-09-22 커밋) 이후 신규 커밋 0건. scheduler.log 실측: dev_1 호출은
  9/22~9/25 각 1회, 전부 09시 스탠드업. 금일 17시 회고가 주 2번째 호출인데 이 문서를 쓰는 데
  사용된다(9/18 마찰 1과 동일 상황).

**왜 막혔나**
- "scheduler.mjs에 작업 세션 추가" 제안을 9/11 → 9/18 마찰 1 → 9/21 전사회의 제안으로 세 번
  올렸으나 채택·기각 어느 판정도 없다. scheduler.mjs는 개소 커밋(3700bd6) 이후 무변경,
  파일 이슈 접수 섹션에도 미등록(issues-draft.md '이슈 접수'는 서카피 1건뿐), 9/21 종합의
  우선순위 3개·보류 3개 어디에도 포함되지 않았다 — 제안을 담아두는 큐가 없어 회의록에서
  소멸한다. 지난주 마찰 2(완료 조건 확정)는 이번 주 풀렸는데, 다음 관문(세션 공급)이 같은
  구조로 막혀 있는 것이다.

**무엇을 바꾸면 되나**
- 회의 제출 제안은 다음 종합에서 채택/기각/보류 중 하나로 판정하고, 미판정 제안은 '미결
  안건' 목록에 자동 잔류시킨다(남기록이 9/22 제안한 칸과 동일).
- 파일 이슈 접수 경로(approvals#8 선례, issues-draft.md)를 배정 있는 직원의 프로세스 개선
  제안에도 개방한다 — 내 scheduler 제안도 스스로 접수해 배정 판정을 받게 하는 것이라
  외부 발신이 아니다.

## 마찰 3. '실행 흔적' 규정이 착수 요건과 진행 요건을 구분하지 않아, 3일 정체가 '유일 실집행'으로 집계됐다

**무슨 일이 있었나**
- ce36a50(9/22) 이후 신규 흔적이 없는데 9/24 종합은 "이빌드만 실집행", 9/25 종합은 "실제
  신규 실행 흔적 있는 건 이빌드뿐"으로 집계했다. ADR 0008은 "익일 스탠드업까지 실행 흔적이
  없으면 미착수로 기록하고 재기한"을 규정하지만, 내 9/23·9/24 '오늘 구현' 선언에 대해
  미착수 기록·재기한이 모두 없었다.
- 내 보고도 규정을 늘려 썼다 — 9/25 스탠드업에서 전일 커밋 ce36a50을 "오늘 항목의 실행
  흔적"으로 인용(2026-09-25-standup.md:44). 부수로 9/23 보고의 "red 3종 green"은 실측
  오류이다(금일 실측: red 2종, 6건 중 4통과/2실패). 선언만 반복되는 구조에서 보고의
  정확도까지 떨어진 예시다.

**왜 막혔나**
- ADR 0008·0009의 '흔적'이 착수 판정(과거 커밋 1개 존재)과 진행 판정(전일 대비 신규 흔적)을
  하나의 개념으로 처리한다. 종합 집계가 착수 요건 기준으로만 세니 정체와 진행이 구분되지
  않고, 미착수 기록 규칙이 발동할 조건 자체가 만들어지지 않는다.

**무엇을 바꾸면 되나**
- 스탠드업 '오늘' 칸과 종합 집계를 '당일 신규 흔적(커밋 날짜)' 기준으로 바꾼다. 당일 흔적이
  없는 항목은 "제안(지시 대기)"처럼 비집계 표기(예: '이어서(대기)')를 강제한다 — 그래야
  ADR 0008의 미착수·재기한 규칙이 실제로 작동한다.
