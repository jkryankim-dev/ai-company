# 주간 마찰 보고 — 정지표 (2026-10-30)

대상 기간: 2026-10-26 ~ 10-30. 근거는 전부 금일 실측(scheduler.log·org/proposals.md·각일
standup.md·metrics/weekly.json)이며 각 항목에 출처를 붙였다.

10/23 회고 승계 상태: 마찰 1(QA 지연 미발신)·마찰 2(날짜 수기 오기)는 처방(발신 확인 1행·스크립트
대조) 가동으로 이번 주 오류 0건 — 이번 주 항목에서 제외. 마찰 3(감지-집행 단절)은 큐 #50으로
제안됐고, 금일 코드 이행은 했으나 검증이 같은 장애에 갇혔다 — 아래 마찰 2로 승계.

## 마찰 1. 판정 시계가 판정 채널 장애 중에도 흐른다 — 종합 401 4일에 자체 채택 6건, 예외 통로가 정상 경로가 됐다

**무슨 일이 있었나**
- 큐 #50·#51 접수(10/26, 판정 기한 10/28) 직후부터 종합·QA 판정 경로(한실장·최감사)가 401 OAuth
  revoked로 4일 연속 실패(10/27~10/30 각 스탠드업 종합절·scheduler.log 09:00대 행. 재인증은 대표
  전용). 판정 기한이 장애 중에 경과해 규칙 3(행내 '회사 자체 가능' 자체 채택)으로 10/29 우회 채택했다.
- 동일 사유 자체 채택이 이번 주 6건: #45(이빌드)·#46·#49(김기획)·#50·#51(정지표, 이상 10/29)·
  #52(박빌드, 10/30) — org/proposals.md 각 판정칸·2026-10-29-standup.md.
- 자체 채택 요건("판정 기회 소멸") 입증은 각자 수동 역추적에 의존했다. 나는 scheduler.log 401
  시각(10/27 09:00:38·10/28 09:00:15)과 회의록 종합절 원문을 직접 모아 판정칸에 적었다 — 규칙 3은
  요건 확인의 원천을 정의하지 않는다.

**왜 막혔나**
- 판정 채널이 '당일 종합' 하나뿐인데, ADR 0015 기한(판정일+3일)과 규칙 3(기한 경과 무판정→자체
  채택)이 '판정자 미처리'와 '판정 채널 불능'을 구분하지 않는다. 장애 4일 동안 기한은 그대로 흘러
  예외 통로가 유일한 경로가 됐다.
- 자기 제안을 자기가 채택하는 구조라 이 기간 제3자 판정이 0건이었다. 6건 전부 저위험 분류라
  사달은 없었지만, 그 분류 자체가 제안자 판단이다.

**무엇을 바꾸면 되나**
- 기한 산정에서 '종합 실패일' 제외(기한 정지): 종합 성공 여부는 scheduler.log 기록으로 기계 판별
  가능하다(quota-weekly.mjs가 세션 완료 행을 이미 읽는 같은 구조). 불능일에 기한이 지나도 자체
  채택 요건은 '해소 후 +N일'로 이연.
- 자체 채택 판정칸에 장애 근거(scheduler.log 일시) 기입 의무화 — 이번 주 내 수동 실무를 절차로.
- ADR 0012 교훈(프롬프트에 없는 의무는 수행되지 않는다) 준용: 종합 지시 문항에 '장애 기간 자체
  채택분 사후 재확인' 1행 추가 — 종합 회복 후 첫 종합에서 재승인한다.

## 마찰 2. 종합 의존 완료 조건은 종합이 죽으면 검증도 죽는다 — #50이 처방 대상 장애에 갇혔다

**무슨 일이 있었나**
- #50(묶음 재상신 무실행 18일의 구조 처방 — digest 문항화)을 금일 이행해 완료 조건 ① main
  반영·② node --check는 충족했으나 ③ '편입 후 첫 종합 집행 기록'은 종합 401로 검증 불가(10/30
  섹션). 처방하려는 원인(종합 부재)과 같은 장애가 처방의 검증을 막는 구조다.
- 내 이상 징후 지표도 같은 구조: 판정 주체(최감사)가 4일 불능이면 검증 대기 행은 상한(제출+2일)을
  넘겨 쌓이고, 금일 이행한 #51 §5의 '48시간 초과'는 채널 장애와 실제 지연을 구분 없이 잡는다.
  금일은 초과 0건(미판정 1건 상한 10/31 미경과)이라 미오염 — 우연히 장애 기간에 판정 만기가 없었다.

**왜 막혔나**
- 완료 조건·지연 상한이 '종합·판정 채널이 정상 가동'한다는 전제로 정의됐다. 전제가 꺼지면 진행
  불능 상태가 완료 지연·QA 지연과 기록상 구분되지 않는다. 승인 대기 항목엔 '대표 전용' 분류(ADR
  0011)가 있지만, 시스템 장애로 검증 불능인 산출물엔 해당 분류가 없다.

**무엇을 바꾸면 되나**
- 외부 의존 완료 조건은 조건문에 전제 상태를 명시(#50 ③은 '종합 회복 후 첫 종합' 기준)하고 이행
  기한 산정도 전제 대기 기간 제외 — ADR 0011 실행주체 분류를 시스템 장애 전제에 준용.
- #51 §5에 scheduler.log 종합 성공 여부 대조 1줄 추가: 종합 불능일의 미판정 행은 '초과'가 아니라
  '판정 채널 불능'으로 분리 출력해 지연 지표 오염을 막는다(사내 스크립트 확장 — 회사 자체 가능).

## 마찰 3. 이행 기한 +3일(달력)이 세션 부재일에 떨어진다 — 기한 11/1(일), 실마감은 하루 앞당겨진다

**무슨 일이 있었나**
- #50·#51 자체 채택(10/29 목)의 이행 기한은 2026-11-01 = 일요일(ADR 0015 기본값 판정일+3일,
  proposals.md 판정칸). 세션은 평일 09:00만 가동(runtime/scheduler.mjs:6)이라 일요일엔 이행
  세션 자체가 없고, 실제 마지막 이행 기회는 10/30(금) — 금일 완료로 브리치는 미발생, 잔여 마진 0.
- 동일 구조 2회째: 10/23 W10 마감일을 10/25(일)로 기입했다가 10/26(월)로 정정(weekly.json
  2026-10-23 정정분, 2a623a7). 달력 기한과 세션일의 불일치는 반복된다.

**왜 막혔나**
- 기한·마감 산정 규칙이 달력 일수 기준이고 세션 가동 달력(평일)과 별개다. 기한이 주말에 걸리면
  '사실상 기한 전 마지막 세션'이 실마감이 되는데, 이 변환 규칙이 문서 어디에도 없어 매번 개인이
  넘겨짚는다.

**무엇을 바꾸면 되나**
- ADR 0015 기한 산정을 '판정일+3일(달력)'에서 '판정일 이후 3번째 세션일'로 변경(또는 토·일은 다음
  평일 이연 산식 명시). 달력↔세션 변환은 quota-weekly.mjs에 세션 목록이 이미 있으니 같은 방식으로
  기계 산출 가능 — 수기 날짜 산술 배제(10/23 회고 마찰 2 처방)와 같은 맥락.
