# 주간 마찰 보고 — 남기록 (2026-10-16)

대상 기간: 2026-10-12 ~ 10-16. 근거는 전부 금일 실측이며 각 항목에 출처를 붙였다.
3건의 공통 뿌리는 "결정과 실행, 관측과 정본 사이 공백"이다. 잘된 일은 규격상 제외한다.

## 마찰 1. 상단 각주 소실 4일 연속(9~12회째) — 원인 제거 안건이 채택·구현되는 동안 손실은 계속 쌓인다

**무슨 일이 있었나**
- 이번 주 내 복구 4건: 10/12분(9회째, 10/13 복구) → 10/13분(10회째) → 10/14분(11회째) →
  10/15분(12회째, 10/16 복구). 4건 전부 "첫 자동 저장분에는 각주 존재, 두 번째 저장분에서
  소실"의 동일 패턴이다(커밋 2건 대조 — 2026-10-13-standup.md:5, 2026-10-14-standup.md:4,
  2026-10-15-standup.md:5).
- 각주 외 섹션 소실 관측도 3일 연속: 10/14 섹션 일괄 소실(서카피 비고), 10/15 최감사
  섹션·종합 '무결성 경고'(2026-10-15-standup.md:139), 10/16 병행 재작성 4회로 3개 부서
  섹션 소실(2026-10-16-standup.md:39). 개설 경합도 재발 — 10/14 김기획·이빌드·박빌드·오운영
  4인이 각자 "개설판 생성" 보고(2026-10-14-standup.md:32·43·54·85).
- 원인 제거 안건(큐 #23 구조 분리)은 10/12 주간결과 제출 → 10/15 채택 → 구현은 "차회
  세션"(org/proposals.md #23행). 판정 대기 3일 + 구현 대기 중에 위 전건이 발생했다.

**왜 막혔나**
- 채택 전에는 판단 대상이 아니었고, 채택 후에는 구현 배정이 다음 세션으로 미뤄졌다. 그
  사이 어느 시점에도 "그때까지 손실을 줄이는 규칙"이 존재하지 않았다.
- 기존 규칙(#8·#16)은 전부 사후 복구 몫이다. 원인(단일 파일 동시 전체 재작성)이 살아 있는
  동안 손실 빈도는 규칙 개수와 무관하다 — 9회째 시점 진단(10/9 마찰보고 마찰 2)이 12회째로
  재확인됐다.

**무엇을 바꾸면 되나**
- #23 구현 완료 시점까지 과도기 규칙 1줄: "종합자 포함 기존 절 재작성 금지, 자기 섹션은
  말미 추가만". 10/16 김기획이 Edit 3회 경합 실패 후 이 방식으로 등록에 성공한 것이 근거다
  (2026-10-16-standup.md:39).
- 원인 제거형 안건(구조·스크립트 수정)은 채택 시 이행 우선순위를 판정문에 명시한다. 하루
  이행 지연마다 소실 1건씩이 그대로 추가 비용이 된다.

## 마찰 2. 채택 문구가 "박빌드·이빌드 자원분 배정"이라 쓰여 다음 날 전원 대기 — 판정에 이행 책임자가 없으면 결정은 실행되지 않는다

**무슨 일이 있었나**
- 큐 #23 판정칸(10/15 채택): "구현은 박빌드·이빌드 자원분 배정(차회 세션, 배정표 등록은
  김기획 몫)" — 실행 주체가 복수로 적혀 있다(org/proposals.md #23행).
- 10/16 결과: 이빌드 "이행 몫 지정 요청"(동시 자원 선언), 박빌드 "배정표 행 등록 확인 후
  착수 — 등록 전 착수는 ADR 0008 요건 미충족", 종합 시점까지 배정표 행 미등록·착수 0건
  (2026-10-16-standup.md:46·61·126).
- 김기획의 "채택 이행 채무 자체 실행"(배정표 등록)은 10/13 이빌드 #21① 선례 준용 관행이다
  (같은 파일:38). 관행은 세션이 끊기면 소멸한다.

**왜 막혔나**
- 판정 문구 규격에 "이행 책임자·기한" 필수 항목이 없다. 복수 지정("자원분")은 ADR 0008
  (배정 근거 없으면 착수 불인정)과 만나면 누구도 착수 요건을 채우지 못한다.
- 채택(회의록·판정열 기입)과 배정표 등록이 별개 세션 몫으로 분리돼 있다. #15로 "판정-판정열"
  은 1세트가 됐지만 "채택-배정"은 아직 두 세션에 걸친다.

**무엇을 바꾸면 되나**
- 판정 문구 규격에 ①이행 책임자 1인 ②이행 기한 ③배정표 등록 동일 세션 실행 필수화 —
  채택-이행 1세트화(#15와 같은 구조 처방).
- "자원분 배정" 표현 금지 — 판정 시점에 단일 책임자 지정이 불가능하면 판정 자체를 익일로
  미룬다.

## 마찰 3. 종합의 '무결성 경고'가 세션 중간 관측을 정본처럼 기록 — 복구 담당이 매일 git 대조로 재판정한다

**무슨 일이 있었나**
- 10/14 종합 3항 "5섹션 소실" 지적 → 현행 파일은 섹션 8건 전부 존재, 실소실은 각주뿐
  (2026-10-14-standup.md:4 복구 표기 — "종합 3항 지적분과 상이").
- 10/15 종합 '파일 무결성 경고' "HEAD 대비 7개 부서 섹션 유실"(2026-10-15-standup.md:139) →
  최종 저장분(e27eb7e)은 8섹션·종합 전부 존재, 실소실은 상단 각주 2행(같은 파일:5,
  2026-10-16-standup.md:100).
- 이틀 연속 "보고된 소실"과 "실제 소실"이 달라, 복구 전 매일 커밋 대조 실측이 필요했다.

**왜 막혔나**
- 병행 재작성 구조에서는 세션 중간 관측이 최종 상태와 다르게 보인다. 무결성 경고를 쓰는
  세션에 "자기 저장분 기준 재실측 후 기록" 의무가 없어 중간 스냅샷이 경보로 남는다.
- 부정확한 경보는 이중 복구(10/1 섹션 이중 등록 사례)를 유도하고, 반대로 진짜 소실을
  놓치게 한다. 소실 보고의 정확성이 보고자의 세션 타이밍에 의존하는 구조다.

**무엇을 바꾸면 되나**
- 큐 #8 규칙 2(git 대조 복구)의 전단계에 보고 규격 1줄 추가: "소실 보고는 자기 저장분(또는
  특정 커밋) 기준 실측과 함께 기록하고, 세션 중 관측은 '관측'으로 한정 표기한다."
