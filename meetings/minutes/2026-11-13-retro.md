## 마찰 1 — QA 판정이 검증자 세션 하나에 묶여 있고, 막혀도 만료 규칙이 없다

**왜 막혔나**: 판정(ADR 0006)이 최감사 단일 세션에 배정돼 있는데 그 세션이 401으로 14영업일째 실패(scheduler.log 금일 09:00:29 재발, 종합절 실패 원문 2026-11-13-standup.md). ADR 0007·0011은 '승인 대기'에만 기본 동작을 정의한다. '검증 대기'에는 #8 별건식 만료 규칙(상한 경과 시 주 1회 묶음 전환, qa-log #8항) 같은 것이 없어서, 초과 행은 매일 §5 카운트만 올라간다.

**무엇을 바꾸면 되나**: 검증 대기 행에도 만료 규칙을 일반화하고(상한 N일 경과 시 조치 전환), 검증자 세션 장애 시 차순위 검증자 대리·또는 제출자 셀프 검증 기록+사후 승인 경로를 ADR로 정한다.

## 마찰 2 — GitHub 이슈 표기와 배정표 정본이 어긋나는데, 바로잡을 도구가 잠겨 있다

**무슨 일이 있었나**: 11/9 제출한 #8 배정 요청이 11/11 기각됐다 — 배정표 정본은 #8 이빌드 배정(org/assignments.md:19행). 그런데 매일 종합 현황에는 #8이 지금도 '담당:없음'으로 출력된다. 오운영도 #3(배정표 9/21 종결 vs GitHub open)의 동일 구조를 지적(11/13 섹션, 지시 대기).

**왜 막혔나**: 정본은 배정표인데 동기화 수단(gh CLI)이 토큰 없이 불가 — approvals #11(gh 토큰, 대표 전용, 53일 대기). 토큰 없이 읽는 범위에서 현황을 배정표로부터 파생시키는 규칙도, 불일치를 탐지하는 절차도 없다. 결과적으로 배정 요청이 정본 확인 후 기각되는 비용이 매번 반복된다.

**무엇을 바꾸면 되나**: 현황 목록을 배정표에서 파생 생성(스크립드)하거나, ops-daily-check §5에 정본-표기 불일치 탐지를 추가하고 불일치 시 현황에 각주를 다는 규칙을 만든다.
