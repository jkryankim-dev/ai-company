# 주간 마찰 보고 — 김기획 (2026-10-23)

대상 기간: 2026-10-19 ~ 10-23(직전 회고 10/16 이후). 근거는 전부 금일 실측이며 각 항목에 출처를 붙였다.

지난 보고(2026-10-16-마찰보고-김기획.md) 3건 잔여:
- 마찰 1(제안의 큐 등록 무의무): 이행 — 큐 #35 채택(10/22 종합) → 금일 이행 완료(feat/35-weekly-proposal-queue-ref d1b7cb9,
  node --test 2/2). main 반영은 대표 전용 대기(이번 주 마찰 3).
- 마찰 2(채택→배정→착수 3단 3세션): 부분 이행 — 판정문 이행 주체 지정이 #34·#35("이행: 김기획",
  2026-10-22-standup.md 종합)에서 실측됐고 배정표 행 등록도 채택 익일 세션에 실행했다. 잔여: 이행으로
  새로 필요해진 실행 배정(#5-빌드·#6-기술 웹조회 2건)은 여전히 종합자 몫으로 차기 종합까지 이월된다.
- 마찰 3(대표 전용 대기 이슈의 선행 과업 부재): 이행 — 큐 #34 채택(10/22) → 금일 소급 4건 갱신 완료.
  신규 접수분에 대한 상시 적용 장치는 없어 이번 주 마찰 2로 이어진다.

## 마찰 1. 섹션 제출과 종합이 같은 09:00 창에서 경쟁해, 금일 종합이 제출 완료된 내 섹션을 '미제출'로 정본 기록했다

**무슨 일이 있었나**
- 금일 종합 ■요약 5항: "김기획 섹션 미제출(금일 파일 공란) — 큐#34 이행 로그는 배정표에 있으나 본인
  스탠드업 보고 누락"(`2026-10-23-standup.md:117`). 그러나 섹션 파일은 존재한다 —
  `meetings/minutes/2026-10-23-standup-pm.md`(개설 각주 '부재 실측 후 신설', 보고 본문·근거 완비).
  종합자 판독 시점과 내 제출 시점이 같은 창 안에서 엇갈린 것으로 본다(순서는 확정 불가, 기록 불일치는 확정).
- 같은 주에 pm 섹션 파일은 10/20·10/22·10/23 3일 모두 부재 상태로 시작해 매번 내가 직접 개설했다
  (각 파일 개설 각주). 개설 몫은 '당일 해당 부서 최초 세션'(가이드 §2)인데 그 세션이 종합 세션과
  동시 기동이라 개설·제출·병합 판독이 전부 같은 시간 창에서 경쟁한다.

**왜 막혔나**
- 가이드 §3-3은 "제출 시각은 당일 세션 내"만 규정하고 제출 컷오프를 정하지 않는다. 전 직원 스탠드업
  세션이 09:00 동시 기동(`runtime/scheduler.mjs:6`)이라 '종합자가 먼저 읽으면 미제출'이 구조적으로 가능하다.
- 섹션 병합 스크립트화(88c03c6, 10/19)가 main 미반영이라 병합·부재 판독이 전부 수동이다(가이드 §3-5
  과도기). '미제출' 기록 전에 배정표 갱신 로그 등 산출물 정본과 대조하는 절차도 없다.
- 메인 회의록이 회의 정본이라 오기가 그대로 남고, ADR 0009(익일 미착수 기록·재기한)와 만나면 실제
  착수자에게 불이익으로 전이될 수 있다. 금일은 배정표 갱신 로그 10/23(김기획)이 병존해 오기임이 입증됐다.

**무엇을 바꾸면 되나**
- 종합자 루틴 1줄: '미제출' 기록 전 섹션 파일 절대경로 재확인 + 배정표 갱신 로그 대조(ADR 0006
  '산출물 정본 우선' 준용). 회사 자체 가능.
- 가이드 §3-3에 컷오프 1줄: 종합 기준 시각 이후 도착 섹션은 '미제출'이 아니라 '지각 제출' 상태값으로
  구분해 기록한다.
- 섹션 파일 전일 예비 개설(전일 종합자가 익일분 부서 셸 8종 생성)로 '부재→당일 개설' 반복을 없앤다.
  근본 해소는 88c03c6 main 병합이다(마찰 3).

## 마찰 2. 지시서 규격 결함 1건이 발견될 때마다 '소급 전수 패치' 안건이 하나씩 생긴다 — 이번 주 2차 패치에 반나절 전량을 썼다

**무슨 일이 있었나**
- 큐 #34 이행으로 지시서 4건(#5·#6·#8 스펙·신청서 잔여)에 '선행 과업' 칸을 소급 신설했다
  (issues-draft.md §#5·§#6 각 '선행 과업(2026-10-23 신설)' 행 외 2건). '환경 전제' 칸도 같은 방식의
  1차 패치다(issues-draft.md:50·71 '환경 전제(2026-10-12 추가)').
- 결과: 금일 내 반나절 배정 전량이 신규 가치(다음 단계 실행 배정)가 아니라 2주 전 산출물 보정에
  소진됐고, 그 보정으로 가능해진 실행 배정 2건은 또 종합자 몫으로 이월됐다.

**왜 막혔나**
- 사규 3조·ADR 0012는 검증 방법의 '미실측'·'대표 발신 전제' 표기를 요구할 뿐, 지시서 작성 시점에
  검증 주체(자체/대표 전용)·선행 과업·환경 전제를 검사하는 체크리스트가 작성자 규격으로 존재하지
  않는다. 결함은 배정·이행 단계가 아니어야 할 때 발견된다.
- 사규 본문 개정은 대표 전용 대기다(10/16 보고 이후 무진행). 개정 전 쓸 임시 템플릿도 없어, 결함
  발견마다 제안→채택→소급의 3단 루프(각 최소 1영업일)가 반복된다.

**무엇을 바꾸면 되나**
- issues-draft.md 상단에 신규 접수용 체크리스트 3줄을 고정한다 — ① 검증 주체 분류(자체/대표 전용)
  ② 대표 전용 값 의존 시 '값 도착 전 자체 가능 선행 과업' 명시 ③ 환경 전제 인용(runtime/docs/ops-env.md).
  신규 접수분부터 적용해 소급 안건을 더 만들지 않는다. 회사 자체 가능.
- 회고 채택 시 위 3줄을 배정표 운영 규칙(10/23 신설 '선행 과업 명시')과 한 세트로 편입한다.

## 마찰 3. 완료된 이행이 main 반영 대기 스택에만 쌓인다 — 스택 5건, 선두 24일째, 깊이에 상한·경보가 없다

**무슨 일이 있었나**
- 금일 내 #35 이행(d1b7cb9, 테스트 2/2)이 병합 대기 스택 5번째로 들어갔다. 스택 실측(git log, 10/23):
  c982a6b(09-29, #8 하위2 — 24일)·f6395bf(10-12, 판정열 동일 세션 기입 — 11일)·a7dadc0(10-13,
  큐 #21① — 10일)·88c03c6(10-19, 섹션 병합 지시 — 4일)·d1b7cb9(10-23, 큐 #35).
- 스택 안 패치는 main 반영 전까지 효력이 없다. 88c03c6(섹션 병합)가 갇힌 사이 이번 주 마찰 1의
  '미제출' 오기가 발생했고, 판정 상태 오독(오운영 "#32·#33 무판정" — 10/23 종합 ■충돌/중복)도
  같은 주에 재현했다.
- 병합 충돌 사전 검증 안건(이빌드 dry-run 제안)은 10/20 제안 → 10/23 3차 재제안까지 판정 대기 중이다
  (2026-10-23-standup-dev.md 이빌드 섹션). 스택이 깊어질수록 검증 몫이 커지는데 그 검증마저 판정 큐에 있다.

**왜 막혔나**
- 'main 병합·재기동'은 대표 전용 분류(ADR 0011·큐 #17 준용)라 대기 자체는 규정대로다. 문제는
  완료→반영 사이 경과·깊이 상한이 없어 스택이 단조 증가하고, 반영 지연 비용(패치 무효 기간·병합
  리스크)을 깊이 기준으로 집계하는 지표가 없다는 것이다.
- 경과일 보고는 정지표 블로커칸에 있으나(10/23) '깊이'로는 집계되지 않고, 해소는 전적으로 대표
  세션에 의존한다.

**무엇을 바꾸면 되나**
- 종합 루틴 1줄(회사 자체 가능): 병합 대기 스택을 매일 종합에 '깊이+선두 경과일' 1행으로 고정 노출 —
  정지표 경과일 집계와 한 세트로 묶는다.
- 운영 규칙: 스택 깊이 상한(예: 3건) 초과 시 묶음 재상신을 주 1회(ADR 0011)에서 즉시 1회로 전환한다.
- 문서·스크립트 전용 변경(runtime/ 스크립트·테스트)의 병합 권한 부분 위임은 대표 건의 사항이다 —
  회고에서 상정 여부를 정한다(선택지: 부분 위임 / 현행 유지+깊이 상한 강화).
