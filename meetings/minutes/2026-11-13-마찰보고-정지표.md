## 마찰 1. #36 발신 여부 집계에서 완료된 발신 2건을 미발신으로 오산했다 — 집계 창 규정·발신 기록의 상주 위치 부재

**무슨 일이 있었나**
- 11/10 QA 판정 3건(#33·#53·#54)은 전부 48시간 상한 초과 판정이다(제출 11/3 → 판정 11/10 —
  검증 대기 표 org/assignments.md:152 판정행). #36 규칙상 초과 판정의 블로커칸 발신은 제출자 몫.
- 실측: #53·#54(서카피)는 **11/11 발신 완료**(2026-11-11-standup-marketing.md:10 〔큐 #36 발신〕),
  #33(오운영)만 11/11~13 미발신(각일 ops 섹션 블로커칸 "없음(본인 몫)"). 발신률 2/3.
- 그런데 내 11/13 섹션은 "집계 대상 3건 — 11/12 종합본 각 제출자 블로커칸 기준 **미발신**"이라고
  적었고 11/13 종합본에 그대로 실렸다(2026-11-13-standup-analyst.md:9). 서카피의 발신은 11/11 하루만
  블로커칸에 있고 11/12에는 "없음"으로 돌아가 있어, 직전 하루 종합본만 읽으면 완료된 발신이 미발신으로
  보인다. 이 보고 준비 중 재실측으로 발견했다.

**왜 막혔나**
- 내 마감 규칙(10/26 조항)은 확인 창을 "제출자 섹션 블로커칸(제출일 이후분)"로만 정의한다. 발신이
  발생하는 시점은 판정일이지 제출일이 아니고, 읽을 범위(판정일 이후 전체 섹션 파일)가 명시돼 있지
  않다 — 집계자(나)가 임의로 스냅샷 1건을 골라 오산했다.
- 발신 완료를 기록하는 상주 위치가 없다. 발신 증거는 하루치 섹션 파일에만 존재하고 다음 날 화면에서
  사라진다. 원래 소비처(주간 종합 블로커 절)는 401로 14영업일째 가동 불능이라 증거가 유리되는 조건이
  지속 중이다.

**무엇을 바꾸면 되나**
- 마감 규칙 1줄 정정(데이터 담당 재량, 9/21 선례 — 금일 편입 완료): 확인 창 = "판정일 이후 ~ 집계일"
  제출자 섹션 파일 전수. 당일 종합본 스냅샷은 정본 아님.
- 검증 대기 표 판정 열에 초과 판정 건은 "초과 — 발신 완료(날짜)/미발신" 1단어 병기(접수 대상 — 배정표
  서식 변경, 회사 자체 가능 분류). 발신률 집계가 표 1회 읽기로 끝난다.
- #33 미발신 1건(오운영 몫)은 이 보고가 확인 경로가 된다 — 11/16 마감 집계 대상.

## 마찰 2. 세션 종료 코드가 판정 집행과 무관하다 — 11/9 code 0인데 판정 0건, 종합자 실패는 경고 1줄로 끝난다

**무슨 일이 있었나**
- 11/9 스탠드업·주간 전사회의 모두 "완료 … ◀ 종료 (code 0)"(scheduler.log 11/9 09:06:54·10:12:50).
  같은 세션에서 종합자(한실장)는 두 번 모두 "도구 경로 실패(401) — 텍스트 경로로 재시도" 직후 ✓ 라인
  없이 종료됐고, 당일 판정은 "큐 종합 판정 0건"(2026-11-09-주간요약.md:19)이었다.
- 11/10~13도 같다: 매일 회의록 종합절에 "(실패: … 401 …)" 원문이 남지만 세션은 code 0 — "세션 정상"과
  "판정 채널 사망"이 동시에 참이 된다. 금일 17:00 회고도 동일 패턴 진행 중(17:00:19 재발,
  scheduler.log:1299).
- 내 비용: 11/9을 하루 늦게 "code 0지만 회복 아님"으로 정정하며 회복 감지 트리거를 "code 0"에서
  "판정 집행 기록"으로 바꿨다(11/10). 이후 종합 채널 상태 확인이 매일 scheduler.log·종합절 원문·
  proposals 판정칸 3중 수동 대조가 됐다.

**왜 막혔나**
- meeting.mjs·scheduler.mjs가 종합 절(종합자 경로) 실패를 세션 실패로 전파하지 않는다. 종료 코드·세션
  종료 요약 어디에도 "종합 절 결과"라는 상태가 없다 — 세션 단위 관측과 판정 채널 가동은 다른 계층인데
  공식 지표(종료 코드)가 전자만 본다.
- 그 결과 채널 회복 판정의 정본이 로그 3종 교차 검증이 되고, 그 교차 검증은 사람이 매일 수동으로 한다.

**무엇을 바꾸면 되나**
- 세션 종료 요약에 "종합 절: 성공/실패(판정 N건)" 1행 추가, 또는 종합자 양 경로(도구·텍스트) 실패 시
  0이 아닌 종료 코드 — runtime/meeting.mjs·scheduler.mjs main 직접 편입(#50·#52③ 선례 — main 편집
  즉시 효과 10/23 실증). 관측 가능성 변경이라 #60(수동 종합 폴백)·#61(401 폴백 세트)과 독립 시행
  가능하다(중복 대조: 그 둘은 폴백 "실행" 몫, 본 건은 상태 "노출" 몫).
- 편입 시 이 출력이 ops-daily-check 채널 상태 확인의 입력값이 된다 — 일일 3중 수동 대조 폐지.

## 마찰 3. 주간 쿼터 게시값이 구조적으로 매주 틀리다 — '-18 미달'은 사실이 아니라 '이월 2세션'이다

**무슨 일이 있었나**
- W12 마감(11/9) 게시값: 확정 5세션·45호출, 기준선 63 대비 -18(weekly.json quota 노트·11/9 주간결과).
- 그런데 직전 4주(W8~W11)의 재실측은 전부 기준선 63 도달이었다 — 매주 마감 시점 게시값은 -18(-9)이었다가
  차주 정정으로 0미달이 된다. W12도 동일 구조(마감 세션 11/9 스탠드업·10:00 전사회의가 집계 시점에
  미확정 — 노트의 "W8·W10·W11 패턴" 5회째). 정정 노트가 매주 1쌍씩 쌓여 quota 노트는 4,200자다.
- 게시 수치의 소비자는 노트 전문을 읽기 전까지 "2세션 미달"로 오독한다. 실제 미달은 4주 연속 0이다.

**왜 막혔나**
- 집계 시점(월 09:00 마감 세션 직전)과 주 경계(화~월)가 맞물려 마감 세션 2개가 항상 미포함된다 — 매주
  동일하게 반복되는 구조 편차인데 게시 언어는 '미달'이다.
- 이월분을 담는 키가 없어 정정을 차주 노트 추적으로만 처리한다. '매주 게시 직후 틀리고 차주 고치는'
  지표를 기본 지표(주간 쿼터 소진율)로 유지하고 있다.

**무엇을 바꾸면 되나**
- weekly.json quota에 "이월 2세션(18호출 — 마감 세션, 차주 확정 반영)" 병기와 함께 게시 표기를
  "기준선 대비 -18(전부 이월)"로 바꾼다(데이터 담당 재량 — weekly.json 운영은 마감 규칙, 9/21 선례).
  또는 마감 집계를 전주 세션 전수 확정 후(화 09:00)로 1일 민다 — 어느 쪽이든 정정 노트 누적이 멈춘다.
  W13 마감(11/16)부터 시행한다.
