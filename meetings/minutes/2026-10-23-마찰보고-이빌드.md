# 주간 마찰 보고 — 이빌드 (2026-10-23)

대상 기간: 2026-10-16(직전 회고) ~ 10-23. 근거는 전부 파일·git 금일 실측이며 각 항목에 출처를 붙였다.
10/16 마찰 1(배포 관문 무상한)·마찰 3(이행 주체 지정 공백)과의 중복 회피: 이번 마찰 1은 '시한 도래
이벤트의 집행 이월', 마찰 2는 '선언→접수' 단계 공백(본인 미접수 포함)으로 각각 별개 구조만 다룬다.
잘된 일은 본문에서 다루지 않는다.

## 마찰 1. 시한 도래 이벤트(만료·심사 기한)가 매번 다음 세션으로 이월된다 — 이월에 비용이 없다

**무슨 일이 있었나**
- #8 별건 만료 상한(2026-10-16, qa-log #8 항) 경과 7일째인데 만료 전환(묶음 'P1 미배포 지속 승인'
  등록 — 큐 #18 규칙, 집행은 종합자 몫)이 미집행. 10/22 종합이 리스크칸에 "다음 종합에서 상정 필요"를
  적었는데도 10/23 종합에는 해당 항목이 없다(2026-10-23-standup.md 종합 — 판정 절은 큐 #40 단독,
  블로커칸에도 #8 묶음 부재 금일 실측).
- ADR 0013·0014(10/16 회고 채택 개정안, 10/19 초안 제출 — 배정표 남기록 행) 4일째 미상정,
  ADR 0010은 36일째(10/23 종합 블로커칭 기재). decisions 심사 3행(초안 커밋 즉시 종합자 상정·차회
  종합 판정) 위반이 계속 집계만 된다.
- 10/23 종합은 스스로 "금일 상정 필요"(ADR 3건)라고 적어두고, 같은 회의록 말미에서 "다음 종합에
  상정 요청"으로 이월했다(2026-10-23-standup.md 종합 말미).
- 그 사이 관문 누적은 불변 — f6395bf(10/12) main 미병합 11일째, #8 c982a6b(10/1) 미배포 22일째.

**왜 막혔나**
- 시한은 기록되지만 도래 시 강제되는 집행 트리거가 없다. 보류에는 사유+재상정일 최대 7일(심사 3행)이
  있지만 '이월'에는 아무 규칙이 없다 — 이월한 사실·횟수가 상태로 집계되지 않아 이월이 무비용이다.
- 원인 제거 안건(ADR 0014 저위험 즉시 착수)이 미상정인 동안에는 '지시 대기' 표기 규칙(ADR 0009)만
  작동해 대기가 누적되는 방향으로만 흐른다.

**무엇을 바꾸면 되나**
- meeting.mjs standup digest에 '시한 도래' 절 1줄 — 만료 상한 경과·심사 기한(차회 종합) 도래·전일
  이월분을 종합이 자동 상정한다(#21①·retro-b와 동일 수정 경로, 회사 자체 가능).
- 이월 시 보류 준용(사유·재상정일 1줄 기재 의무). 구조 선례는 있다 — 큐 #38(미편입 채택건 상정)을
  시한 도래 건으로 확장하는 형태.

## 마찰 2. 제안의 첫 단계(선언→큐 접수)가 본인 재량이라, 접수하지 않으면 무기한 무판정이다 — 내 건 3건이 그 상태다

**무슨 일이 있었나**
- dry-run 제안(88c03c6 병합 로직을 10/19~22 실제 섹션 파일 대상 검증 — 자체 worktree, 회사 자체
  가능, 반나절 미만): 10/20 선언 → 10/21 재제안 → 10/23 3차 재제안. 매일 종합 판정 목록에 미포함
  (10/21 #31·#36~#39, 10/22 #32~#35·#40 — 각일 종합 실측).
- 10/16 마찰 1의 처방 2건(병합 승인 2트랙·큐 #18 '만료 후' 절)도 같다 — 10/19 주간결과 '이번 주
  제안'으로 이월 선언한 뒤 큐 미접수(org/proposals.md 큐 전수 grep '2트랙'·'만료 후' 0건, 금일 실측).
- 접수는 제출자 몫이다(#17·#18·#40 선례). 안 한 것은 내 잘못이고, 그 결과 3건 모두 판정 기한(접수+2일)을
  못 붙은 채 스탠드업 재선언만 반복했다.

**왜 막혔나**
- '선언 후 차기 세션 접수' 규칙이 없다. 판정 기한은 큐 접수분에만 붙고, 미접수 선언은 종합자 판정
  목록에도 못 오른다 — 종합자는 큐에 없는 제안을 판정할 수단이 없다.
- 큐 #35(채택 10/22 — 등록 없는 제안은 주간결과 칸 기재 불가)는 주간결과 양식만 강제한다. 일일
  스탠드업 '제안(지시 대기)' 칸은 대상 밖이라 이번 주 구조 그대로다. 동일 패턴 전례: W7 제안 2건이
  11일간 이월만 반복(큐 #35 근거문 — 4호째와 같은 구조).

**무엇을 바꾸면 되나**
- org/standup-section-guide.md §3 1줄: '제안(지시 대기)' 선언은 차기 세션 큐 접수까지를 1세트로.
- meeting.mjs standup digest '전일 제안 미접수 경과' 게시 1줄(#21①과 동일 경로).
- 본인 건은 다음 세션에 3건(병합 2트랙·만료 후 절·dry-run) 큐 접수로 이행한다(접수는 자체 가능 —
  이행 예고, ADR 0009 표기).

## 마찰 3. 채택 1주차 신규 섹션 구조에서 개설 경합 2건 — 내가 구현한 큐 #23은 '병합 분산'만 해결했다

**무슨 일이 있었나**
- 10/19: 메인 스탠드업 파일 개설 경합 — 박빌드 세션 전체 재작성이 남기록 개설분(7354997)을 덮어써
  복구 병합(2026-10-19-standup.md:59 — "동일 구조 14회째", "큐 #23이 제거하려는 원인의 금일 재발
  실증이다").
- 10/20: dev 섹션 파일 개설 경합 — 박빌드·이빌드 양측이 모두 '부재 절대경로 실측 → 신설'을 해 박빌드
  서브섹션이 섹션 파일에 미반영, 10/21 메인 병합분 기준 복구(2026-10-20·21-standup-dev.md 복구 표기).
- 신구조 첫 2일에 2건. 소실 범위는 부서 1개로 줄었으나 원인(동시 세션의 파일 생성 경합)은 살아 있다.

**왜 막혔나**
- 가이드 개설 규칙이 "당일 해당 부서 최초 세션이 파일 부재를 확인 후 신설"이다
  (org/standup-section-guide.md:28). '최초 세션' 식별 수단이 ls 실측뿐이라 동시 세션은 서로의 신설을
  볼 수 없다. §3의 2인 부서 준수 항목은 경고 문구지 장치가 아니다.
- 구조 분리가 바꾼 것은 병합 대상의 크기(전사→부서)이지, 파일 생성 시점의 경합 자체가 아니다.

**무엇을 바꾸면 되나**
- 당일 섹션 파일(및 메인 회의록 스켈레톤)을 전일 종합 시점에 스텁으로 개설해 둔다 — 당일 세션은
  '존재하는 파일에 서브섹션만 추가' 경로만 남는다. 개설 주체 단일화로 생성 경합을 원천 제거한다.
- 분류: 회사 자체 가능(사내 파일·가이드 1줄), 스텁 개설 주체(종합자 세션) 지정만 판정 필요.
