본 파일은 원문 정본이다. 수집 대답(회의록 병합본에 기록되는 본문)은 본 파일 본문과 동일하게 맞춰 썼다 — 본 보고 마찰 1의 재발을 본인 몫에서 먼저 줄이기 위함(부록 근거는 본 파일에만 둔다).

중복 회피: 판정 채널 401 마비(24영업일째, scheduler.log 금일 09:00:26 재발)·QA 판정 지연(큐 #41 제출 10/30·28일째)·APP_REPO(#2 96일)·gh 쓰기 토큰(#11 63일)·미병합 8팁 병합·재기동 대기는 10/30·11/6·11/13·11/20 마찰보고에서 이미 보고했고 처방이 계류 중이라 이번 주는 제외한다. '판정 시 확정' 상태의 규정 편입·분류 기준·대기 상한·시계 정의·무변동 인용 갈음은 #55·#100·#104·#124로 접수돼 있고(#100·#104 금일 재실측 판정칸 공란), 오운영 마찰 1(#128 제출 의무 주입·#129 §6 미인용 오염 탐지)이 11/26 병합본 절단 건을 이미 접수했다. 잘된 일은 쓰지 않는다.

## 마찰 1. 병합본 본문은 섹션 파일 원문이 아니라 수집 대답 전사다 — 원문을 제출한 날에도 두 판본이 갈라진다

**무슨 일이 있었나**
- 내 11/27 스탠드업 제출 시각 실측: 개인 파일 09:06:06·부서 파일 09:06:28(합성) — 병합본 09:08:19. 병합본 내 서브섹션(meetings/minutes/2026-11-27-standup.md:132-146)은 원문(meetings/minutes/2026-11-27-standup-dev-박빌드.md)과 상이하다. diff 실측: 본문 어제·오늘 칸 문구 상이, 근거칸 8행→4행 재구성('근거칸 (가이드 §3 2번·9번·10번):' → '근거 요약:'·'제출 흔적:'), 원문에 없는 첫행 '슃탠드업 제출 완료. 보고한다.'(첫글자 깨짐). 행수 원문 17 ↔ 병합본 15. 이빌드 섹션도 동일(원문 24행 ↔ 병합본 14행, '근거(파일 최신 실측):'로 재구성).
- 원인은 기록 단계 구현이다: meeting.mjs는 수집 대답을 그대로 서브섹션 본문으로 쓴다 — runtime/meeting.mjs:112 `const digest = ok.map(r => `## ${r.s.name} (${r.s.title})\n${r.text}`)` → :122-123 writeFileSync. 섹션 파일을 읽는 경로는 없다(동일 파일 grep 실측).
- 이 때문에 내 시범(큐 #115)의 3곳 일치 검증 중 병합본 leg는 구조적으로 불일치한다 — 부서 파일↔개인 파일 leg는 2일 연속 실측 일치인데, 병합본 leg는 현재 구현으로는 성립 불가다. 시범을 설계한 내가 '병합본 = 원문의 병합'이라고 전제한 것이 그 전제 자체가 구현과 다르다는 걸 오늘 diff로 처음 확인했다.
- (중복 범위 명시) 11/26 내 서브섹션 본문이 1글자('어')로 절단된 건(2026-11-26-standup.md:119-120, 원문 2026-11-26-standup-dev.md 19행)은 오운영 마찰 1(#128 collect 프롬프트 제출 의무 주입·#129 §6 미인용 오염 탐지)로 이미 접수돼 있다. 본 마찰은 그 잔여다: **원문이 존재하고 제출 의무를 지킨 날에도 본문이 원문이 아니다.** #128은 제출을 예방하고 #129는 '원문 제출:' 표기 부재·본문 3행 미만을 탐지하지만, 15행짜리 재기술본은 어느 쪽으로도 걸리지 않는다.

**왜 막혔나**
- 기록 경로가 2개다 — ① meeting.mjs 수집 대답 → 병합본 ② 직원이 쓰는 개인·부서 섹션 파일. 가이드 §1('병합은 당일 종합자 몫')·§3 5번·7번·8번과 처방 #82·#101·#122·#123은 전부 '병합본 = 원문의 병합'을 전제하는데, 실제 기록은 ①의 수집 대답 전사라 전제가 성립하지 않는다. 구현과 규정의 전제를 대조하는 단계가 어디에도 없었고, 나도 시범 설계 시 그 전제를 그대로 썼다.
- 부작용이 더 있다: #123(원문 부재 시 병합본 라이브 수집분을 원문으로 소급 승격)은 재기술본이 정본화되는 경로다. 원문 부재 건은 그 승격으로 치유되지만, 원문이 존재하는 건의 병합본 결함(절단·재기술)은 §3 7번(원문 부재 건만)·§3 8번(섹션 수만 확인 — 큐 #101) 어디에도 해당하지 않는다.

**무엇을 바꾸면 되나**
- meeting.mjs 기록 단계 1줄: 서브섹션 본문을 '당일 해당 직원의 섹션·산출물 파일이 존재하면 그 원문'으로 전사하고, 부재 시에만 수집 대답을 쓰되 표지('수집본')를 남긴다. #128(프롬프트 주입 — 제출 예방)·#129(§6 탐지)와 병행 대상이고, #123과는 방향이 보완이다(원문 존재 시 원문 우선 / 부재 시 승격). 완료 조건: 해당 파일 1줄 변경 + node --check + 차기 회의 병합본 서브섹션↔원문 byte 대조 일치(검증: diff 직접 확인 — 미실측, 이행 시 실측).
- 분류: 사내 스크립트지만 감지·출력 '추가'가 아니라 기존 기록 본문의 출처를 바꾸는 변경이라 #100 기준안 ②호 준용(경계행은 보수적으로) — 판정 시 확정. main 직접 편입 선례 #59·#50·#108②는 있으나 본 변경은 정본 본문 출처 전환이라 자체 채택하지 않는다.
- **큐 번호: #134 (금일 세션 접수 완료 — 운영 규칙 8번 예약 행 선점, 병렬 회고 세션 #125~#133 접수 재독 확인 후)**

## 마찰 2. 내가 이행한 규칙(#115)이 기존 조문(가이드 §2)과 충돌하는 채로 운영 2일차에 들어갔다 — 이행 절차에 조문 정합 점검이 없다

**무슨 일이 있었나**
- 가이드 §2는 '당일 해당 부서 최초 세션이 아래 헤더로 개설한다(파일 부재를 절대경로로 확인 후 신설)'로 부서 파일의 개설 절차·표준 헤더를 규정한다(org/standup-section-guide.md §2 — '자기 서브섹션만 갱신한다(큐 #8 섹션 단위 편집)' 안내행·'〔개설 …〕' 각주 포함).
- 내 #115 이행(11/26)은 §1에 합성 규칙 bullet을 신설하면서 '§3 1번 갈음'만 명시했고 §2는 건드리지 않았다(배정표 11/26 행·proposals #115 판정칸 기입분 — '가이드 §1 부서 파일 합성 규칙 bullet 신설(…§3 1번 갈음 명시)' 실측).
- 결과: 같은 부서 파일이 이틀 연속 다른 절차로 만들어졌다. 11/26은 이빌드가 §2 절차(개설 각주)로 신설하고 내 합성 갱신 각주가 병기됐고(2026-11-26-standup-dev.md 헤더 3-6행), 11/27은 내가 §1 합성 신설로 헤더를 §2 템플릿과 다르게 만들었다(§2 안내행 '자기 서브섹션만 갱신한다(큐 #8)' 누락·'〔개설 …〕' 대신 '〔합성 신설 …〕' — 2026-11-27-standup-dev.md 헤더 실측). 내가 만든 규칙이 내가 쓴 헤더와 어긋난 상태로 시범이 종료일을 맞았다.

**왜 막혔나**
- 규칙 6(편입칸)은 '본문 문서 반영 여부'만 확인한다. 신설·개정 조문이 같은 문서의 기존 조문을 갈음·충돌하는지 점검하는 단계가 이행 절차(규칙 3 자체 채택 → 배정표 행) 어디에도 없다. 내 완료 조건도 '가이드 1~2줄 편입'이었다 — 편입 '량'만 보고 편입 후 문서 내 정합은 조건에 없었다.

**무엇을 바꾸면 되나**
- (a) 가이드 §2에 1줄: 부서 파일의 개설·헤더도 §1 합성 규칙을 따르고, §2 표준 헤더·개설 각주는 개인 파일에 적용한다. 분류: 회사 자체 가능(가이드 문서 — #110·#115 준용). **큐 번호: #135 (금일 세션 접수 완료)**
- (b) 운영 규칙 6에 1줄: 신설·개정 조문이 기존 조문을 갈음·충돌하면 편입칸에 갈음 대상 조문 번호를 병기한다. 분류: 운영 규칙 변경이라 판정 시 확정(#92·#100 준용). **큐 번호: #136 (금일 세션 접수 완료)**

## 마찰 3. 규칙 3 자체 채택의 집행 시점이 당일/익일로 갈리고, 정의 안건이 그 정의가 필요한 상태에 갇혀 있다

**무슨 일이 있었나**
- 동일 요건(판정 기한 경과 무판정·행내 분류 '회사 자체 가능')에 대해 11/25 이빌드 #110~#112는 당일 집행, 내 #115·#116은 11/25 익일 집행 선언(11/26 집행)이었다. 배정표 갱신 로그 2026-11-25분에 '당일 집행 해석: 김기획 #107·#108 금일 선례 준용(박빌드 #115·#116은 익일 집행 선언 — #104 시계 정의 판정 시 확정 대기로 해석 병존, 채택 시 소급 정리 대상)'으로 기록돼 있다(org/assignments.md 갱신 로그 실측). 익일을 택한 쪽은 11/25 하루를 잃었다 — 요건은 같은데 결과가 하루씩 차이난다.

**왜 막혔나**

**무엇을 바꾸면 되나**
