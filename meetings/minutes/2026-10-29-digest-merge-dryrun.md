## 차이·결함 목록 (지시 6으로 재현·탐지되지 않는 것)

1. **누락 탐지 단위 부정합** — 지시는 '누락 부서' 단위인데 실제 미제출·소실은 개인 서브섹션 단위로 발생: ① 10/19 dev 파일에 이빌드 서브섹션 부재(시범 1일차 박빌드만 제출)·메인에는 이빌드 섹션 존재 ② 10/21 dev 파일에 이빌드 서브섹션 부재 — git 이력 전수(단일 커밋 929b280)에도 부재 실측, 메인 병합분에만 존재(직접 기입 또는 미저장 소실, 이력상 판별 불가) ③ 10/23 pm 파일 세션 시점 공란(메인 종합 기록 "김기획 섹션 미제출(금일 파일 공란)"). dev 2인 부서의 1인 누락은 '부서' 단위 지시로 탐지 불가.
2. **세션 후 제출분 재병합 규정 부재** — "이 세션 안에 병합" 요건상 종합 세션 이후 도착한 제출(10/23 pm — 현재 파일은 작성돼 있고 메인도 병합됨)은 지시 6 범위 밖. 후속 처리(재병합·보류 표기) 문항 없음.
3. **병합 형식 불명시** — 직원 섹션 헤더 형식(`## {이름} ({직무})`)·3줄 블록 원문 보존·근거 절 압축 여부를 지시가 규정하지 않음. 말미 "원본을 옮기지 말고 압축하라. 14줄 이내."가 병합분에도 적용되는지 모호 — 실제 병합분은 3줄 블록 원문 보존 + 근거 압축 혼용(14줄 이내와는 양립 불가 구조).
4. **비표준 구조 파일 처리 규정 부재** — 가이드 §2 이전 제출분(10/19 pm·ops: `## {이름}` 서브섹션 없는 구조)의 병합·검증 방식 미지정. 실제로는 종합자가 판독 병합(정상 작동).
5. **역방향(메인 직접 기입) 감지 부재** — 섹션 파일 없이 메인에 직접 기입된 섹션(10/19 이빌드·10/19~20 최감사 — qa 섹션 파일은 10/21 개시)은 지시 6 대상 밖. 가이드 §1 "제출자가 메인 파일을 직접 편집하지 않는다" 위반 여부 확인 경로 없음.

## 부가: 누락 부서 선언 실측

지시 6의 "누락 부서를 밝혀라"는 실제 5일 종합 어디에도 시행되지 않음(10/19 종합은 제출 3부서만 나열, qa·analyst·librarian·chief-of-staff 부재 무언급 — main 미병합으로 지시 6가 종합자에게 전달되지 않은 탓과 일치). chief-of-staff는 5일 전일 미제출.

## 지시 6 문구 개선안 (dry-run에서 도출 — 채택 여부는 종합자·대표 판정 대상)

1. 누락 탐지 단위를 부서에서 직원 서브섹션으로: "각 섹션 파일의 `## {이름}` 서브섹션 전수를 메인과 대조해 누락 직원을 밝혀라" (결함 1)
2. 세션 후 제출분 문항: "세션 시작 시점 공란·부재였다가 이후 도착한 섹션은 재병합 후 도착 시각을 남겨라" (결함 2)
