  기록했다(2026-10-14-standup.md:117).
- 10/15: 보고 등록 중 파일 2회 덮어짐, 재등록·재독 검증(2026-10-15-standup.md 내 비고). 같은 날
  최감사 섹션 소실(박빌드 세션 직접 독취분으로 복구). 10/16도 김기획 등록 중 재작성 4회·3개 부서
  섹션 소실 관측(2026-10-16-standup.md 김기획 근거 요약). 상단 각주 소실은 12회째(2026-10-15-standup.md:5).
- 해결 안건 큐 #23(구조 분리): 10/13 접수 → 판정 기한 10/15(접수+2일) → 10/15 종합 채택 →
  배정표 등록·구현 자원 지정은 10/16 세션 이월 → 금일 회고 시점 착수 전. 접수부터 착수 전까지
  4일, 그동안 결함은 매일 재발했다.

**왜 막혔나**
- 판정 기한이 '접수+2일'로 균일하다. 매일 재발해 손실이 누적되는 결함과 단발 제안이 같은 대기
  시간을 가진다 — 긴급도 구분이 없다.
- 원인 제거(#23) 이행 전의 임시 완화 수단이 없다. 사후 복구 규칙(#8·#16)과 구조 분리(#23) 사이
  공백 기간에 재발 빈도를 줄일 절차가 하나도 운영되지 않았다. 10/9 마찰보고에서 제안한 종합자
  diff 대조 루틴은 회고 미채택으로 남아 있다.

**무엇을 바꾸면 되나**
- proposals 운영 규칙 1항 추가: 재발 관측 중인 결함 안건은 판정 기한 접수+1일.
- 큐 #23 이행 완료 시점까지 종합자 루틴에 '직전 자동 저장 커밋 대비 금일 회의록 diff 대조 1회'를

**무슨 일이 있었나**

  (김기획 #14 선례)' 논리를 세워 스스로 배정해야만 실행할 수 있었다(2026-10-13-standup.md 내 섹션 근거).
- 큐 #23: 10/15 채택 문구는 "배정표 등록은 김기획 몫"까지만 지정(org/proposals.md:50) — 구현 자원은
  미지정. 이빌드·박빌드가 각자 자원 선언(10/14·10/15)으로 이원화돼 금일 종합 '충돌·중복' 항목에
  "지정 필요"로 올라왔다(2026-10-16-standup.md 종합). 박빌드는 "배정표 행 등록 확인 후 착수 — 등록
  전 착수는 ADR 0008 요건 미충족" 상태로 대기 중이다.
- 결과: 금주 실행 흔적은 10/12·10/13 이틀(회고 B·큐 #21①)뿐이고 10/14~16 3일 연속 '오늘' 칸은
  전부 제안(지시 대기)·실행 흔적 없음(각일 스탠드업 내 섹션).

**왜 막혔나**
- 1세트화(#15)는 판정→판정칸 기입까지만 세트다. '이행 주체 지정'은 세트 밖이라, 지정이 빠지면
  이행은 선례 준용·자원 선언·차세션 지정 같은 우회 경로를 거쳐 매번 하루 이상 지연된다.
- ADR 0008(배정 근거 없는 착수는 미착수)은 착수 남발을 막는 규칙이지만, 지정 공백 상태에서는
  합법적 대기로 전환돼 채택 이행을 오히려 지연시키는 방향으로 작동한다.

**무엇을 바꾸면 되나**
- 큐 #15 1세트 범위 확장: 판정 문구에 이행 주체('구현: 누구 / 배정표 등록: 누구')까지 동일 세션에
  기입한다. 실행 수단도 이미 있다 — meeting.mjs standup digest 판정 지시(f6395bf main 병합분)에
  이행 주체 지정 1줄 추가. 프롬프트 1줄, 회사 자체 가능(큐 #21과 동일 수정 경로).
- 배정표에 '채택 이행 대기' 상태값 추가(큐 #22 "QA 대기"와 같은 구조) — 지정 공백 기간이 미집계
  상태로 숨지 않게 한다.
