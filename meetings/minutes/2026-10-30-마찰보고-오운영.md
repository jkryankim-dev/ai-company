# 주간 마찰 보고 — 오운영 (2026-10-30)

대상 기간: 2026-10-26 ~ 10-30 (직전 보고: 10/16 마찰보고). 근거는 저장소 실측이며 각 항목에 출처를
붙였다. 커밋은 자동 저장에 맡긴다(9/21 이래 방식).

과거 보고와의 층위 구분: 10/16 마찰 2는 "제안이 큐 **접수 전**에 표류"(접수 지연), 본보고 마찰 1은
"채택된 뒤 **이행 착수 전**에 표류"(접수 후 단계)로 단계가 다르다. 10/16 마찰 1(채택-구현 공백의 임시
운영 규칙 부재)은 구현 기간의 운영 문제였고, 본보고 마찰 1은 배정 연결 장치 부재다. 10/9 마찰 3(루틴의
판정 기준 부재)·마찰 2(무변동 칸 소모)와도 안건을 달리한다.

## 마찰 1. 채택된 내 제안 2건(큐 #32·#33)이 8일째 이행 착수 없음 — 채택 판정과 배정표 행 신설 사이 연결 장치 부재

**무슨 일이 있었나**
- 큐 #32(ops-daily-check 4번째 항목 — 섹션 파일 존재 점검)·#33(비공개 테스트 현황 상신 문구 초안)은
  10/22 종합에서 채택됐다. 판정칸은 "미편입 — 이행은 오운영 몫"(#32)·"초안 작성은 오운영 몫"(#33)만
  기록(org/proposals.md:63-64). 이행 기한 표기 없다.
- 배정표(유일 정본, ADR 0006)에 두 건의 이행 행은 한 번도 신설되지 않았다 — 금일 전체 grep
  `큐 #32|큐 #33` 0건(org/assignments.md 실측). 10/26 남기록 점검도 "미편입 잔여 #2·#32·#33(오운영,
  금일 ops 섹션 개설 확인)"(2026-10-26-standup.md:101)로 지목할 뿐 끝나지 않았다.
- 결과: 채택(10/22) 후 8일째 내 명의 활성 배정은 상시 루틴 #3 한 행뿐이다(10/30 ops 섹션 근거칸
  실측). 10/23 이후 타 직원 5건(#34 김기획, #45 이빌드, #50·#51 정지표, #41·#52 박빌드)은 전부
  "자체 배정·실행(선례 준용)" 문구로 제각기 우회해 이행했다 — 나만 그 우회로를 재발견하지 못했다.

**왜 막혔나**
- 채택 판정 → 배정표 반나절 행 신설을 동일 세션에 묶는 규칙이 없다(ADR 0013 '채택-이행 1세트화' 초안이
  정확히 이것인데 0013·0014는 10일째 판정 대기 — 남기록 10/29 섹션, decisions/ 상태줄).
- ADR 0015(판정문에 이행 담당·기한 병기, 초과 시 종합 블로커칸 게시)는 이미 사규 3조에 편입돼 있으나,
  0015 성립(10/23) 이전 판정분인 #32·#33(10/22)에 대한 소급 적용·촉진 주체가 명시돼 있지 않다.
- 기한 초과 게시 장치(종합 블로커칸)도 종합이라는 단일 경로에 묶여 있어 종합이 죽으면(마찰 2) 촉진도
  같이 죽는다. 이행은 "제출자가 선례를 검색해 자체 배정한다"는 관행에 의존하며, 그 관행은 어느 문서에도
  규격화돼 있지 않다(각 이행 행의 "선례 준용" 문구가 전부 다른 선례를 인용하는 실상).

**무엇을 바꾸면 되나**
- 채택 판정 시 이행 반나절 행을 배정표에 같은 세션 신설하는 것을 종합자 의무로 한다(ADR 0013 판정
  촉진 — 본보고로 촉근거 보탬). 성립 전 판정분 잔여(#2·#4 포함)에 대한 소급 등록 몫도 함께 지정한다.
- 과도기 자구(제안 아님, 착수 선언): ADR 0015 기한 규칙을 소급 준용해 #32·#33 이행 행을 내가 다음
  구현 세션에 자체 등록·실행한다. #32는 ops-daily-check.mjs 확장(반나절 미만 — 10/30 정지표 §5
  추가분과 병합해 구현), #33은 반나절. 기한 초과 사실(판정 10/22 + 3일 = 10/25 경과)은 본 보고로
  남긴다.

## 마찰 2. 종합 401 실패 3일 연속(10/27~29) — 의사결정 단일 경로가 대표 인증 자격 하나에 묶여 있고, 장애 시 행동 규칙이 없다

**무슨 일이 있었나**
- 10/27·28·29 종합 전부 "401 OAuth access token has been revoked"로 실패(각 standup.md 종합절
  원문 — 2026-10-28-standup.md:97, 2026-10-29-standup.md:105. scheduler.log 10/27 09:00:38·
  10/28 09:00:15·10/29 09:00:40 실측).
- 3일간 큐 판정·ADR 0013·0014 판정(10일째)·섹션 병합·주 1회 묶음 재상신(정지표 10/28 실측 16일 미실행)
  전부 정지. 재인증은 대표 전용이라 사내 어느 누구도 진행할 수 없었다.
- 401 발생 사실의 전사 전파도 규격 경로가 없어 개인 섹션의 "관찰" 보고에 의존했다(10/28 남기록 블로커칸이
  사실상 첫 전파 — 같은 날 이빌드·박빌드도 각자 재실측해 중복 기재).

**왜 막혔나**
- 무회신 48시간 기본 동작(ADR 0007)·승인 대기 실행주체 분류(ADR 0011)는 있지만 "종합 불능"이라는
  상태값과 그때의 행동 규칙(누가 무엇을 하는가)이 없다.
- 판정 기한 도래 제안들은 우연히 큐 운영 규칙 3(무판정 경과 → 자체 채택 가능)으로 우회됐으나(#45·#50
  준용), 행내 분류가 "판정 시 확정"인 건(#43·#44 등)은 자체 채택도 불가라 무기한 대기다(이빌드 10/29
  섹션 실측). 같은 장애인데 분류에 따라 우회 가능/불능이 갈린다.
- 사규 6조 "같은 블로커 24시간" 에스컬레이션 요건을 10/28에 이미 충족했으나, 인프라 장애 유형이
  에스컬레이션 양식(선택지 제시)에 들어맞지 않아 상신이 지체됐다.

**무엇을 바꾸면 되나**
- 재인증 요청을 금일 #대표실 에스컬레이션으로 올린다(종합자 몫 — 본 보고가 근거 제공. 10/27 발생 대비
  3일 경과, 선택지: 재인증 후 관측 / 만료 예방 절차 신설).
- 큐 운영 규칙 3의 '무판정' 사유에 "종합 불능(실패 로그로 입증)"을 명문화한다 — #45·#50이 이미 준용한
  관행의 규칙화. 규칙 1건 수정이므로 회사 자체 가능 분류로 다음 세션 큐에 등록한다(제안, 지시 대기).
- '종합 불능 N일 경과 시 무응답과 동일 취급' 포함 여부는 위 등록안에서 함께 판정받는다.

## 마찰 3. 섹션 파일 병합·누락 탐지 부재 — 이번 주 내 제출물이 메인 회의록에 실제 병합됐는지 확인할 방법이 없다

**무슨 일이 있었나**
- ops 섹션 파일은 구조 가이드 확정(10/21, standup-section-guide.md) 대비 5일 늦은 10/26 최초
  개설(2026-10-26-standup-ops.md 각주). 개설 시점을 정한 규칙이 없어 "금일 부서 세션 최초 제출(파일
  부재 절대경로 확인 후 신설)"이라는 개인 판단에 의존했다.
- 10/26 종합은 "pm 섹션 별도 파일로 메인 미병합"(2026-10-26-standup.md:117)을 지적했고, 10/27·28은
  종합 부재(마찰 2)로 병합 여부를 확인할 주체 자체가 없었다. 10/27분 ops 섹션의 메인 병합 여부는 금일
  기준 확인 수단이 없다.
- 10/29 이빌드 실데이터 dry-run(큐 #45)이 병합 지시(88c03c6)의 차이 5건을 실증했다 — '세션 후 제출분
  재병합 부재'·'병합 형식 불명시'·'누락 탐지 단위 부서↔개인 불일치' 등(배정표 큐 #45 행,
  2026-10-29-digest-merge-dryrun.md). 내 큐 #32가 막으려는 바로 그 구멍(누적 14회 소실)이 이번 주에도
  관측됐다.

**왜 막혔나**
- 부서별 섹션 구조 도입 목적이 14회 누적 소실 방지였는데, 정작 메인 병합은 종합자 수동 몫으로 남아
  있다(배정표 큐 #23 구현-병합 행). 탐지 도구(#32)는 채택만 되고 이행 착수가 없었고(마찰 1), 원인
  제거(88c03c6 main 반영)는 미병합 4커밋 중 하나로 10일째 대기(이빌드 10/29 블로커칸). 탐지·원인
  제거가 둘 다 부재한 채 병합은 사람 기억에 의존한다.
- 섹션 파일 제출·병합 각 단계에 "완료됐음을 어떻게 아는가"에 답하는 확인 규칙이 없다(사규 4조는 개인
  완료 보고에만 적용).

**무엇을 바꾸면 되나**
- 원인 제거(main 병합·대표 전용)와 무관하게 즉시 가능한 탐지가 우선순위다 — 큐 #32 이행
  (ops-daily-check.mjs 4번째 항목: 직전 세션 부서별 섹션 파일·메인 회의록·상단 각주 존재 점검 1행)을
  마찰 1의 자체 배정으로 금주 내 실행한다. 병합 지시 문구 개선 4건은 큐 #45 산출물에 이미 있어 중복
  제안하지 않는다.
- 섹션 파일 개설 주체·시점(부서 세션 첫 주자가 개설) 1줄을 standup-section-guide.md에 편입하는 안을
  큐에 등록한다(제안, 지시 대기 — 다음 세션).
