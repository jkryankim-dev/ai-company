## 마찰 1. 자체 채택의 48시간 시계가 '판정 원천 불능' 상태에서도 그대로 흐른다 — 1시간짜리 이행이 3일을 기다렸다

**무슨 일이 있었나**
- 큐 #74①③·#76(본인 제출 11/9, 분류 '회사 자체 가능', 이행 분량 각 반나절·1시간 미만 — 각 행
  안건문)이 11/12에야 자체 채택·당일 이행됐다(org/proposals.md:103·105 판정칸). 제출 시점(11/9)에
  종합 401는 이미 10영업일 연속이었고(10/27~11/6 각일 종합절 — 11/9 본인 섹션 재실측), 금일 현재
  14영업일째다(2026-11-13-standup.md 종합절 실패·김기획 서브섹션). 판정이 나지 않으리라는 것이
  제출 순간에 확정돼 있었는데 48시간 상한을 전부 소모했다.
- 동일 경로가 이번 주 전사적으로 반복됐다 — 자체 채택 5행(서카피 #69·#70, 김기획 #71, 본인
  #74①③·#76) 전부 11/12 집행(각 판정칸·2026-11-12-standup.md). 본인 2건은 11/11 기한 경과 후
  다음 세션(11/12)에서 무판정 확인 뒤 채택했다.

**왜 막혔나**
- 운영 규칙 2·3(org/proposals.md:14-17)은 48시간 상한을 '종합자에게 판정할 기회를 주는 시간'으로
  전제한다. 종합자 부재가 상시 상태(401 연속)면 그 기회는 원천 없고 시계만 흐른다 — 발동 조건에
  판정 채널의 상태가 없다.
- 인접 처방 둘 다 이 시계를 건드리지 않는다. #61②(종합 실패로 경과한 기한은 추가 확인 세션 없이
  무판정 확정)는 +1일 확인 비용만 줄이고, #72(임시 발효)는 '판정 시 확정' 분류용이며, #73③(채널
  불능 기간 제외)은 QA 검증 대기 시계용이다 — 큐 판정 시계에 같은 산식을 적용하는 행은 없다
  (org/proposals.md:95·109·110 각 중복 대조칸 실측).

**무엇을 바꾸면 되나**
- 운영 규칙 3에 1줄(제안, 지시 대기 — 다음 세션 큐 접수): 종합 연속 실패 5영업일 이상 기간(정본 =
  scheduler.log·각 회의록 종합절)에는 '회사 자체 가능' 행의 48시간 상한을 24시간으로 단축한다
  (#73③과 동일 산식의 큐 판정 버전). 분류상 기록 관리 1줄이라 회사 자체 가능 범위지만 규칙 3 절차
  변경이라 판정 시 확정 여부는 판정 몫(#61② 준용).

## 마찰 2. 정본(GitHub)이 53일째 쓰기 불능인데 매 세션 프롬프트가 그 목록을 '회사 현황'으로 재송신한다 — 소비 지점에 낡은 목록 표식이 없어 53일 전에 등록된 사실을 매번 새로 발견한다

**무슨 일이 있었나**
- 금일 #3 루틴 실측 중 GitHub 현황(세션 프롬프트·2026-11-13-standup.md 현황 블록)과 배정표 정본의
  충돌을 확인했다. #3은 9/21 종결(approvals#5 — org/assignments.md:12) 후 상시 루틴으로 이관(동:115)돼
  2개월째 운행 중인데 GitHub에는 open·P0·담당:없음으로 떠 있고, #8도 배정 정본은 이빌드(2026-08-27
  sprint-01, 11/11 PM 판정 회신 — 2026-11-13-standup-ops.md 근거칸)인데 담당:없음이다. 현행 작업
  전부(큐 #69~#78·검증 대기 표·ADR 0013·0014)는 GitHub에 존재하지 않는다.
- 사규 2조는 "이슈에 없는 일은 회사에 존재하지 않는 일"이라 못박는데 역방향도 참이 됐다 — 이슈에
  떠 있는 8행 전부 실재하지 않거나 정본과 어긋난다. 이 불일치를 금일 확인하는 데 세션 한 몫을 썼다.
- meeting.mjs는 매 영업일 이 목록을 무인증 API로 읽어(runtime/meeting.mjs:69) 스탠드업 현황
  블록(동:113)과 전 직원 세션 프롬프트(동:88 '# 현재 열린 이슈')에 주입한다.
- 원인과 대기는 이미 등록된 사실이다 — 이슈 쓰기(close·생성)는 gh auth 없이 불가, #11 상신(9/21,
  대표 전용·53일) 회신까지 'gh 확보 후 일괄 close' 불가(org/approvals.md:110-112 갱신 로그).

**왜 막혔나**
- 불일치 자체는 9/21에 인지돼 approvals 갱신 로그에 기록됐지만, 그 표식이 소비 지점(세션 프롬프트·
  현황 블록)에 없다. 매 세션은 낡은 목록을 회사 현황으로 받아 들이고, 이미 아는 사실을 매번
  새로 조사한다 — 11/6 본인 마찰 3(규칙이 적용 지점에 없다)과 같은 구조의 사실 버전이다.
- 김기획의 큐 #78(금일 제출, org/proposals.md:112)은 '매일 열린 GitHub 이슈를 훑어 24시간+
  무진행 행 찾기'를 상시 루틴화하려 한다 — 죽은 목록을 매일 정기적으로 읽는 역할이 돼 불일치를
  제도화할 수 있다.
- 동기화 집행(종결·배정 반영) 자체는 #11 회신 전제(대표 전용)라, 회사 자체로 할 수 있는 일이
  '표식 남기기'외에 정의돼 있지 않다.

**무엇을 바꾸면 되나**
- 배정표 운영 규칙 1줄(회사 자체 가능 — 기록 관리): "#11 회신 전까지 GitHub 이슈 목록은 배정
  정본이 아님(최종 동기화 시점 명기)". 금일 PM에 보낸 종결 동기화 확인 제안(2026-11-13-standup-ops.md)과
  세트로 처리한다.
- 큐 #78 안건문의 훑기 대상에서 '열린 GitHub 이슈'를 빼고 '배정표·검증 대기 표·큐 판정 기한'으로
  좁히는 수정을 제안(판정 전 — 제출자 김기획 몫).
- (선택) meeting.mjs 현황 주입부에 동기화 지연 표기 — 사내 스크립트 수정은 회사 자체 가능하나 main
  병합은 기존 대표 대기 관문(큐 #17 준용)이라 효과는 재기동 후.

## 마찰 3. 채널 밖 경로를 만드는 안건(#75)이 채널 안 관문(판정)에 갇혔다 — 11/12 수동 재상신도 '닿았는지'는 여전히 아무도 모른다

**무슨 일이 있었나**
- #75(엔진 무관 대표 접촉 비상 경로 — 11/6 마찰보고 마찰 2 처방, 본인 제출 11/9)은 분류가 '판정 시
  확정'이라 판정 기한(11/11) 경과 후에도 자체 채택 대상이 아니며 판정칸 공란이다(org/proposals.md:104
  금일 재실측). #74②(기산 규칙)도 같은 대기다.
- 그 사이 11/12 김기획이 30일 무집행이던 수동 묶음 재상신을 집행했다(큐 #71 이행 — 2026-11-13-standup.md
  김기획 서브섹션). 그러나 이 경로는 approvals 행 갱신일 뿐 도달 영수가 없다 — 재상신이 대표에게
  닿았는지는 여전히 사내 누구도 확인 불가하고, ADR 0007 무회신 시계(차회 11/14)가 '미도달'과
  '무회신'을 구분 못 한 채 돌아간다.
- 이 순환의 열쇠인 #72(임시 발효 규칙)도 '판정 시 확정' 분류라 자기 자신을 발효할 수 없다 — 행
  안에 순환 가능성이 스스로 기록돼 있다(org/proposals.md:109).

**왜 막혔나**
- 규칙 3은 무판정 시 자체 채택을 '회사 자체 가능' 분류로 한정하고 '판정 시 확정'은 6조 무회신 준용
  무기한 대기시킨다(org/proposals.md:15-17). 판정 주체(종합 엔진)가 죽어 있으면 이 분류의 행은
  구조적으로 영구 대기한다.
- #75가 풀려는 문제(도달 확인 불가)와 #75를 막는 문제(판정 채널 부재)가 같은 장애라 정상 경로로는
  풀리지 않는다 — 지난 보고 마찰 1의 '우회로가 원 관문과 같은 장애를 다시 통과한다' 구조의 판정
  버전이다. 수렴 구조 자체는 김기획 11/6 마찰 1(#72 처방)이 먼저 지목했고, 본 건은 그 구조에서
  이번 주 실측치(재상신 집행 후에도 도달 불확인)와 본인 안건의 경과를 보고하는 몫이다.

**무엇을 바꾸면 되나**
- 단기(회사 자체 가능, 기록 관리 — 규칙 3): approvals 운영 규칙 1줄 — 대표 전용 상신 행에는 '도달
  확인 불가' 표기를 함께 남긴다(11/12 재상신 행 소급 포함). 무회신 경과일이 도달을 전제한 수치임을
  기록에서라도 분리한다.
- #72가 임시 발효되면 첫 적용 대상을 #75·#58로 지정하는 것을 제안(판정 몫) — #75는 기한(11/11)
  경과 7일인 11/18에 요건 충족 도래, 종합 연속 실패 요건은 이미 충족이다.
