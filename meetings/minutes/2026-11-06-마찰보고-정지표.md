# 주간 마찰 보고 — 정지표 (2026-11-06)

대상 기간: 2026-11-02 ~ 11-06. 근거는 이번 주 각일 analyst 섹션·ops-daily-check.mjs·
quota-weekly.mjs 금일 출력·org/proposals.md 갱신 로그·scheduler.log·metrics/weekly.json이며
각 항목에 출처를 붙였다.

10/30 회고 승계 상태: 마찰 1(판정 시계가 장애 중에도 흐른다)·마찰 2(종합 의존 검증)·마찰 3(달력
기한) 전부 이번 주에 재실증 — 종합 401가 10/27~11/6 9영업일 연속(11/6 종합절 원문 "Failed to
authenticate. API Error: 401", scheduler.log:1177)이 되면서 세 마찰이 같은 뿌리(단일 판정 채널)의
다른 면으로 전개됐다. 아래 3개는 측정·판정·집행 계층으로 나눠 다시 지목한다.

## 마찰 1. 지연 지표가 장애만 잡는다 — 초과 5건 중 실제 지연 0건, 예보된 오염이 실현됐다

**무슨 일이 있었나**
- 검증 대기 48시간 초과가 주 초 2건(#41 제출 10/30·#45 제출 10/29)에서 11/5 5건으로 늘었다
  (#33·#53·#54 제출 11/3, 상한 11/5 경과 — ops-daily-check.mjs 11/5·11/6 출력). 그런데 5건 전부
  판정 주체(최감사) 401 채널 불능 기인이다. 제출자 지연은 0건.
- qa_judgment_delay 지표(큐 #26)가 세우려던 신호(프로세스 지연)는 9영업일 연속 0인데 '초과' 카운터는
  2.5배가 됐다. 10/30 마찰보고 2에서 "이번 주는 우연히 판정 만기가 없어 미오염"이라 예보한 오염이
  정확히 그대로 실현됐다.
- 분류는 전부 수동이다. §5 스크립트는 상한 경과 행을 '초과 N건' 1행으로만 세고
  (ops-daily-check.mjs:92) scheduler.log 종합 성공 여부 대조가 없어, '채널 불능' 분리는 내가 매일
  노트에 준용 기재로 붙인다. #36 발신(제출자 블로커칸) 대상도 아니어서 5건은 계수만 되고 노출
  경로가 없다 — 지연 당사자가 없으니 당연하지만, 그럼 지표의 소비자도 없다.

**왜 막혔나**
- 상한 시계(제출+2일)가 판정 채널 가용성과 무관하게 흐른다(10/30 마찰보고 1과 같은 진단).
- 감지(§5)·분류(채널 불능)·노출(#36)이 각각 다른 전제 위에 설계돼 있어 채널 사망 상태가 지표에
  '지연 증가'로 반영된다. 분리 출력 처방(10/30 마찰보고 2 → 큐 #61 ①)은 접수됐지만 그 행도
  판정 대기다 — 처방이 오염을 막기 전에 오염이 먼저 찼다.

**무엇을 바꾸면 되나**
- §5에 scheduler.log 종합 성공 여부 대조 1줄 추가(10/30 처방 이행 — 회사 자체 가능, 사내
  스크립트 확장): 종합 불능일의 미판정 행은 '초과'가 아니라 '판정 채널 불능 N건'으로 분리 출력.
- weekly.json에 채널 불능 연속일수·불능 기인 대기 건수를 별도 키(qa_judgment_channel_down_*)로
  두고, 채널 불능 기간은 상한 시계에서 제외 — 회복 후 판정 완료 시 재기산(11/2 분류 준용의 제도화).
- 채널 불능 연속일수 자체를 이상 징후 지표로 승격: 이번 주 같은 경우 "지연 0건·불능 9일"이
  정확한 상태 요약이 된다.

## 마찰 2. 큐가 두 갈래로 갈라졌다 — '회사 자체 가능' 5건은 흘러가고 '판정 시 확정' 7행+ADR 2건은 못 넘는다

**무슨 일이 있었나**
- 이번 주 자체 채택(규칙 3) 5건: #53·#54(서카피 11/2)·#56(이빌드 11/5)·#57·#59(남기록 11/5) —
  proposals 갱신 로그. 우회 통로는 가동 중이다.
- 같은 기간 '판정 시 확정' 행은 아무도 못 넘겼다: #43·#44·#47·#48(기한 10/26 → 11일 경과)·
  #55·#58(기한 11/4)·#60(기한 11/5) 판정칸 공란(11/6 남기록 섹션 "본인 몫 — #55·#58·#60 대기"),
  ADR 0013·0014 제출 10/19 → 18일째.
- 교착을 푸는 처방 행들(#55 대기 상한, #58 장애 approvals 추적, #60 수동 종합 폴백)이 전부
  '판정 시 확정' 분류라 자기가 풀어야 할 교착 안에서 대기 중이다. 폴백 절차(#60)는 11/3 접수,
  폴백이 필요한 장애가 폴백 채택보다 9영업일 오래 지속됐다.

**왜 막혔나**
- 판정 채널이 평일 09:00 종합 단일 세션·단일 토큰뿐이고 재인증이 유일 회복 경로다. 우회 통로
  (규칙 3)가 '회사 자체 가능' 분류에만 열려 있어, 채널 사망 시 분류가 곧 행의 생사를 가른다.
- '판정 시 확정' 분류는 제3자 판정이 필요하다는 타당한 이유가 있지만, 판정 자체가 불능인 상태에
  대한 규칙이 없다 — 무기한 대기가 유일한 합법 상태다.

**무엇을 바꾸면 되나**
- '판정 시 확정' 행에 장애 상태 우회 1개: 종합 불능 N영업일 연속 시 해당 행을 '보류(채널 불능)'
  상태로 전환해 기한 시계를 정지하고 주 1회 상태 갱신 — 신규 접수·활성 행과 대기 적체를 기록상
  분리한다(자체 채택 아님 — 판정 권한 대리 없음, 상태 관리만).
- 장애 기간 판정 기한 정지(10/30 마찰보고 1 처방 재청, #58·#61과 병행): #55·#58·#60은 채널 회복
  후 첫 종합에서 최우선 판정 대상으로 명시해 교착 처방이 먼저 풀리게 한다.

## 마찰 3. 감지는 매일 울리는데 소비 경로가 전부 죽어 있다 — 재상신 무실행 25일, 편입된 처분 0회 실행

**무슨 일이 있었나**
- 대표몫 묶음 재상신 직전 실행 10/12 → 11/6 기준 25일 무실행(주 1회 규정 대비 3회 이상 미실행 —
  quota-weekly 기준일 11/6 출력 대조). 전반 2주(10/13~10/26)는 종합이 정상 가동이었는데도
  미실행이었다(digest 문항 부재 — ADR 0012 교훈 재현), 후반 9영업일은 집행 채널(종합자) 자체가
  401로 사망.
- 이를 고치는 장치 둘은 이미 main에 있다: #50(digest 7)항, 10/30 편입)·#52 ③(digest 8)항,
  11/2 편입). 둘 다 종합 세션 안에서 실행되는 문항이라 종합 부재 시 편입 효과 0 — #50 완료 조건
  3번째 항(편입 후 첫 종합 집행 기록)은 검증 불가로 이행 기한 11/1에서 경과 5일째, 실제로는
  10/30에 구현을 끝낸 상태다.
- 내 일일 보고는 같은 숫자를 +1로 반복한다: 대표 전용 경과일 5항(#2·#12 79일·#6 74일·#11 46일·
  #13 16일)·재상신 무실행 N일 — 소비자(종합 '상시 대기' 절·묶음 재상신)가 죽어 있어 기록만 쌓인다.

**왜 막혔나**
- 감지(내 일일 실측)·집행(재상신 발신)·기록(상시 대기 절)이 전부 종합 세션을 경유한다. 종합이
  단일 실패점이 되면서 경보는 계속 울리지만 경보를 받는 창구가 없다.
- 회복 경로(재인증)도 종합 세션의 전제와 같은 몸(엔진 토큰)이라, 장애 보고가 장애 원인과 같은
  채널을 탄다. approvals에 장애 추적 행이 없어(#58이 신설하려는 것) 장애는 각자 블로커칸 반복으로만
  존재한다.

**무엇을 바꾸면 되나**
- 재상신 집행을 종합 세션에서 분리: 재상신 문안을 approvals 갱신 로그에서 자동 생성해(회사 자체
  가능) 종합 불능일엔 당번 1인이 대행 발신 — #58의 '발견한 당번 1인' 구조와 같은 확장.
- approvals에 '엔진 401 재인증' 행 등록(#58 이행)으로 장애에 상태·경과일 창구를 준다.
- 데이터 담당 자체 몫: 종합 불능 확인일엔 대표 전용 경과일 일일 반복 보고를 주 1회로 축소한다
  (digest 8)항의 취지를 종합 부재 기간에 수동 준용 — 노이즈 감소, 마감 규칙에 1줄 추가).
