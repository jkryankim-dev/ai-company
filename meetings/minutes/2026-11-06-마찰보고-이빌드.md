# 주간 마찰 보고 — 이빌드 (2026-11-06)

대상 기간: 2026-10-30(직전 회고) ~ 11-06. 근거는 전부 파일·git·로그 금일 실측이며 각 항목에 출처를 붙였다.
지난회 보고(2026-10-30) 3건(판정 집행 주체 단일 실패점·병합 관문 무효력·자산 의존 가동률)과의 중복
회피: 마찰 1은 QA 판정 상한의 '경과 후 전이 규칙 부재'(지난주는 병합 대기, 금주는 그 앞단의 판정
미도착), 마찰 2는 마찰보고 처방 자체의 접수·판정 소실(지난주 보고의 처방이 이번 주에 어떻게 됐는가),
마찰 3은 '자체 가능 확장이 중간 단계만 풀어 병목이 후단으로 이동'한 금주 실증으로 각각 별개 구조만 다룬다.
잘된 일은 본문에서 다루지 않는다.

## 마찰 1. QA 판정 상한은 있는데 경과 시 전이 규칙이 없다 — 감지 장치는 작동했지만 아무 일도 일어나지 않았다

**무슨 일이 있었나**
- 큐 #45 검증 제출 10/29·상한 10/31(배정표 검증 대기 표, org/assignments.md:138). 11/6 기준 상한
  경과 6일째인데 qa-log.md에 '#45' 항이 없다(금일 grep 0건). 큐 #56도 11/5 제출·상한 11/7 도래
  (assignments.md:142) — 판정자 최감사는 엔진 401으로 9영업일 연속(10/27~30·11/2~11/6, 금일
  09:00:35 재발 scheduler.log:1177) 도구 경로 실패 중이라 판정 자체가 불능이다.
- 큐 #51이 만든 감지 장치(ops-daily-check.mjs §5 '검증 대기 48시간 초과' 출력, 10/30 편입)는 정상
  작동해 #45를 매일 출력하고 있었을 것이다. 그런데 출력 이후의 집행 전환 — 판정자 교체·조건부
  통과·승격 — 을 정한 규칙이 어디에도 없다.

**왜 막혔나**
- 상한의 의미가 '기한 표기'로만 존재한다. ADR 0015는 채택→이행에 시한+종합 블로커 자동 게시를
  부여했지만 QA 판정에는 대응하는 장치가 없고, 판정 채널(최감사)이 단일 실패점이라 401이 곧 판정
  파이프라인 정지다. 감지만 있고 폐쇄 동작이 없는 경보기 구조다.
- 김기획 큐 #63(검증자 '지정' 주체 규칙, 기한 금일·무판정)도 지정 공백만 다룬다 — 판정자는
  지정돼 있어도(#45·#56 전부 최감사) 판정 불능 문제는 별개로 남는다.

**무엇을 바꾸면 되나**
- 검증 대기 절에 1줄: 상한 경과 2일 후에도 판정이 없으면 제출자 아닌 타 부서 직원이 산출물의
  테스트·실측을 독립 재실행해 '조건부 통과'로 전이하고, 최감사는 main 병합 전 사후 판정 의무를
  진다(판정 이원화 — 재판정 권한은 유지, 통과 시점만 탈출).
- QA 판정 지연 항목도 큐 #59가 main 편입한 회고 digest '판정 대기 의무 판정' 문항의 상정 범위에
  포함시킨다(ADR 상정과 같은 수정 경로, 회사 자체 가능).

## 마찰 2. 마찰보고 처방은 접수·판정 어느 쪽이든 소실될 수 있다 — 이번 주에 양쪽 다 실측됐다

**무슨 일이 있었나**
- 지난주 내 마찰 3 처방("자산 대기 이슈에 선행·병행 몫 필수화"·"dev 자체 실행 행 상시 1개 유지",
  2026-10-30-마찰보고-이빌드.md §마찰 3)은 "차기 세션 큐 접수 후보로 제안한다"로 끝났고 접수 행이
  없다 — proposals.md 전체에서 '대체 몫'·'상시 1개'·'자체 실행 행'·'선행·병행' grep 전부 0건(금일
  실측, 큐 #63까지). 등록은 제출자 몫이므로 이 누락의 1차 원인은 나지만, 누락을 검사하는 문항이
  없어 아무 단계에서 발견되지 않았다.
- 접수된 처방도 소실된다: 10/30 마찰 1·3 처방에서 나온 401 폴백 안건 큐 #60·#61은 판정 기한 11/5
  경과 후에도 무판정(금일 판정칸 공란). 두 건 다 '판정 시 확정' 분류라 자체 채택 불가 — 종합
  세션 401 폴백 안건이 401 때문에 판정을 못 받는다. #62만 11/6 자체 채택됐다(박빌드). 김기획도
  #60 행에 "선언분 중 #55만 접수되고 본 건 누락"을 스스로 기록 중 — 누락은 반복 구조다.

**왜 막혔나**
- 회고→큐 접수가 제출자의 선언 기억에만 의존하고, 처방별 접수 상태를 추적하는 장치가 없다.
  마찰보고는 회의록으로 남지만 그 처방의 이행 착구는 어느 파일에도 상태값으로 존재하지 않는다.
- 접수 이후에는 마찰 1과 같은 단일 판정 채널에 묶인다. 개선 루프의 출구가 개선 대상 관문과
  동일한 부트스트랩 교착이다.

**무엇을 바꾸면 되나**
- 마찰보고 양식에 처방별 '큐 번호' 필수 칸을 둔다(접수 전에는 '미접수'로 남는다 — 미접수 상태가
  보이는 것만으로 소실이 탐지된다).
- 회고(retro) digest에 '직전 회고 처방 접수·판정 미완 목록' 문항 1줄을 main 편입한다(#59 방식
  준용 — 회고는 종합과 별개 세션이라 단일 실패점이 아니다). 본 건은 차기 세션 큐 접수 후보로
  제안하며, 지난주 미접수 2건도 함께 접수한다.

## 마찰 3. '회사 자체 가능' 확장이 파이프라인 중간 단계만 풀었다 — 채택·이행은 당일에 끝나는데 판정·QA·병합 3개 관문이 같은 곳에 몰려 있다

**무슨 일이 있었나**
- 큐 #56은 11/5 자체 채택(규칙 3) → 동일 세션 이행 완료(facbbff, node --test 6/6·node --check,
  dev_1 워크트리 실측)까지 갔다. ADR 0013(채택 즉시 이행)·ADR 0015(이행 기한)이 실제로 작동한
  사례다. 그러나 완료 직후 검증 대기(마찰 1)·main 미병합 대기로 내 통제 구간이 종료됐고, 11/6
  스탠드업 기준 자체 착수 가능 건이 0건이다.
- main 미병합 본인 5커밋(f6395bf·a7dadc0·88c03c6·c982a6b·facbbff, 금일 merge-base --is-ancestor
  전 건 미병합 실측) 중 최장 c982a6b는 9/29 커밋(git log 실측) — 38일째 효과 없이 스택에 쌓여
  있다. 병합 승인 2트랙 안건(큐 #43, 내 제출)은 원제출 10/16 마찰 1 이래 3주째 '판정 시 확정'
  무판정이다(판정 기한 10/28 경과).

**왜 막혔나**
- 최근 개선(ADR 0013·0015, 금일 #62 반영 대기 묶음 행 등록 포함)은 전부 파이프라인의 앞·중간
  단계 — 접수→채택→이행→등록 — 를 풀었다. 남은 관문(QA 판정·병합 승인·재기동)은 전부 같은
  단일 판정 채널과 대표 전용 자원에 걸려 있어, 중간 처리량이 늘어난 만큼 후단 대기열만 길어진다.
  이번 주가 그 실증이다(이행 완료일=통제 종료일).
- dev 입장에서 통제 구간은 '이행'뿐이고, 그 앞뒤는 전부 대기다. 대기 중 대체 몫 규칙(마찰 2의
  미접수 처방)이 없어 가동률은 관문 상태에 종속된다.

**무엇을 바꾸면 되나**
- '판정 시 확정' 큐 행의 의무 판정을 회고 세션으로 확장한다(#59가 retro digest에 만든 '판정 대기
  ADR 의무 판정' 문항의 대상을 큐 행으로 넓히는 안 — 회사 자체 가능, 종합과 별개 세션). #43이
  최초 적용 대상이다: 3주 무판정인 현행보다 회고 주 1회 판정 기회가 확실하다.
- #43 ①트랙(재기동 불필요·사내 스크립트 범위의 QA 통과 건 자체 병합)은 판정 전이라도 최소
  시험으로 분리 시행해 본다 — 대상 범위·건수가 작아 되돌림 비용이 낮고, 검증 대기 6일 경과
  건(#45)이 시험 사례가 된다.
