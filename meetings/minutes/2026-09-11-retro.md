## 최감사 (QA·코드리뷰 총괄)
지난 4일(9/8~9/11) 스탠드업 실측 기준, 겪은 마찰 3건.

**1. PR 파이프라인 부재로 QA 실무 진입 자체가 막힘**
- 무슨 일: 9/8~9/11 나흘 연속 "PR 없음, 배정 이슈 없음, 리뷰 대기 재확인"만 반복 보고함. #8은 9/8 "착수" 선언됐지만 9/11 확인 결과 `feat/8-gateway-persist` 브랜치가 main 대비 커밋 0건(`git log main..feat/8-gateway-persist` 빈 결과).
- 왜 막혔나: 이슈 완료 조건이나 사규 어디에도 "PR 생성 시점"이 QA 진입 트리거로 정의돼 있지 않다. 개발이 "착수"를 선언해도 실제 diff가 생기기 전까진 리뷰할 대상 자체가 파이프라인에 없어, QA는 매일 같은 부재 확인만 반복하게 된다.
- 무엇을 바꾸면 되나: 이슈 완료 조건에 "PR/브랜치 diff 존재"를 진입 조건으로 명시하고, 커밋이 처음 발생하는 시점에 QA 채널로 알리는 규칙을 추가한다.

**2. gh CLI 미승인(17일째, approvals.md #3)으로 표준 리뷰 큐 확인 불가**
- 무슨 일: 원격 PR 목록을 정식 방법으로 조회하지 못해 매일 "gh 미설치 → main만 존재 → 로컬 git 실측" 절차를 반복 수행함.
- 왜 막혔나: 승인 큐(org/approvals.md #3)가 17일째 무회신으로 쌓여 있고, 이 대기가 QA의 일일 확인 비용을 매번 발생시키는 구조로 방치돼 있다.
- 무엇을 바꾸면 되나: gh CLI 승인 여부와 무관하게 로컬 git diff/log 기준으로 "리뷰 큐"를 정의하는 대체 절차를 문서화해, 승인 대기와 QA 확인 절차를 분리한다.

**3. QA 대상 산출물(신청서 10문항 전수검증) 자체가 아직 존재하지 않아 착수 시점 트리거 없음**

## 1. 결정 확정에서 ADR 등록까지 4일 — 전환 담당·기한이 여전히 없다
- **있었나**: 배정·검증판정 정본 단일화는 9/4 확정, ADR 등록은 9/8 (`decisions/0006...md:3`). 사이 3일간 decisions/ 최신은 8/18의 0005였다 — 사규 9조가 정한 작업 전 조회 대상에 결정이 없었다. 9/4 회고에서 지적했던 문제이고(`2026-09-04-retro.md:157`), 9/7 전사회의가 "다음 세션 착수" 몫을 지정해서야 풀렸다. 규칙이 아니라 몫 지정이 우연히 풀었다.
- **막혔나**: 사규 8조는 "결정은 ADR로"까지만 있고 누가·며칠 안에 전환하는지가 없다. 회의록에 확정 사실이 남아 있으니 "이미 기록됐다"고 읽혀 전환이 밀린다.
- **바꾸면**: 회의 종합 양식에 결정마다 "ADR 번호(예정) / 전환 담당 / 기한 = 차회 스탠드업 전" 칸 추가. 종합 양식은 기록 관리 사항이라 별도 승인 불요(approvals.md 선례). 기한 내 미전환은 종합 블로커에 자동 인용.

## 2. 상신한 항목이 approvals 표에서 4일간 사라져 있었다
- **있었나**: 9/4 회고가 6조 개정안을 상신했는데 같은 날 내가 표를 갱신하며 행을 누락했다. 9/8 보완(`org/approvals.md:37`, "내 실무 오류" 명시). 4일간 9/7·9/8 종합이 "#1~#9 전건 무회신"을 낡은 표 그대로 인용 — 사실은 10건이었다. 발단은 내 오류이나, 전원이 표를 인용하고도 아무도 못 잡은 구조가 문제다.
- **막혔나**: 상신(각자 행 추가)과 갱신(9/7 확정된 종합자 당번)이 같은 표를 쓰는데 상신 원문과의 대조 절차가 없다. 행 수 정합성은 아무 몫이 아니다.
- **바꾸면**: 갱신 노트에 "상신 원문 경로 + 원문 상신 건수 ↔ 표 행수 대조 결과" 1줄 남기기.

## 3. 기록관 상시 직무가 전부 '제안 → 회신 대기' 사이클을 탄다
- **있었나**: 이번 주 내 배정 이슈 0건. 직무 범위 안의 지식베이스 정리(sprint-01.md 정본 안내 2행 추가)도 제안으로 올렸고 3일 사이클이 걸렸다 — 9/9 제안 → 9/10 기입·커밋(f88e6ab) → 9/11 확인. 9/11 현재도 W4 주간요약 수집을 제안으로만 올린 상태.
- **막혔나**: 사규 2·3조는 신규 업무 기준이다. 상시 직무(회의록·ADR·지식베이스 정리·주간요약)가 제안 대상인지 착수 대상인지 경계 규정이 없어 매번 임의로 좁게 해석한다. "기록 관리 사항 별도 승인 불요" 선례는 있으나 범위 미정의.
- **바꾸면**: 상시 직무는 "반나절 이하 + git 되돌림 가능" 범위에서 제안 없이 착수 후 스탠드업 보고로 종료 — ADR 한 건으로 못박는다. 범위 밖은 현행대로 이슈 경유.
