## 2. 표준 헤더 (섹션 파일 공통)

당일 해당 부서 최초 세션이 아래 헤더로 개설한다(파일 부재를 절대경로로 확인 후 신설 — 스탠드업 파일 경합 선례 9/28·9/29 준용).

```
# 스탠드업 섹션 — {부서 슬러그} (YYYY-MM-DD)

## {이름} ({직무})
(보고 본문)
```

## 3. 작성 규칙

1. 각 직원은 자기 `## {이름}` 서브섹션만 추가·갱신한다. 타인 서브섹션·상단 헤더·각주를 재기입하지 않는다(큐 #8 규칙 1 준용 — 섹션 파일은 부서 단위로 경합 대상을 분산한 것이지 전체 재작성 허가가 아니다. dev처럼 2인 부서는 특히 준수).
2. 보고 양식은 사규 5조 3줄(어제/오늘/블로커)을 그대로 쓰고, 아래에 근거(배정 행·실측 출처)를 붙인다. '오늘:'은 실행 흔적(커밋·브랜치·파일 경로) 있는 항목만 쓴다(ADR 0009).
3. 제출 시각은 당일 세션 내. 병합(메인 회의록 반영·요약)은 당일 종합자가 실행하며 제출자는 자기 병합을 하지 않는다(자기 PR 자기 머지 금지와 동일 구조).
4. 소실 발견 시 큐 #8 규칙 2·큐 #16(기록관 git 이력 대조 복구)을 준용한다. 단, 섹션 파일은 작성자 1~2명으로 한정되므로 "직전 읽은 원문"이 곧 대조 기준이 된다.
5. 과도기: 종합 스크립트 반영(meeting.mjs, 배정표 큐 #23 구현-병합 행 — 이빌드)이 main 반영·재기동(대표 전용)되기 전까지 병합은 수동 실행이다. 병합 누락이 발견되면 차기 종합이 섹션 파일 원문을 그대로 반영한다(소실 아님 — 원문은 섹션 파일에 존재).
