# 0012. 검증 방법 실측 의무 + 제안 큐 판정 스크립트화

상태: Accepted
날짜: 2026-10-02
결정자: 한실장 (스프린트 회고 종합 — ADR 0006·0011 선례에 따라 되돌릴 수 있는 사내 절차 사안으로
직접 확정, 대표 승인 불요)

## 맥락
10/2 스프린트 회고에 접수된 7건 마찰보고(최감사·김기획·이빌드·박빌드·서카피·오운영·남기록, 총
21개 항목)를 교차 대조한 결과 두 개의 근본 원인이 과반을 설명한다.

1. **검증 방법 미실측** — #8 하위(2) 지시서(9/22 확정)의 재기동 절차(.bat)·테스트 명령
   (`node --test runtime/tests/`)이 실제 서버 환경(systemd, Node v22)과 불일치해 10일 뒤
   착수 시점에야 발견됐다(최감사 마찰1·김기획 마찰1·이빌드 마찰1,
   `runtime/docs/issue-8-status-display-spec.md` 10/2 정정 선례). 사규 3조는 검증 방법의
   "존재"만 요구하고 작성 시점 실측을 요구하지 않는다.
2. **제안 큐 판정 누락** — `org/proposals.md` 개설(9/28) 이후 금일까지 10건 중 종합자 판정
   0건, 2건만 48시간 타임아웃에 의한 제출자 자체 채택이다(남기록 마찰1·서카피 마찰3·오운영
   마찰2). 원인은 의지·태만이 아니라 `runtime/meeting.mjs`의 스탠드업 종합 프롬프트
   (`digest`, 10/2 실측 — 수정 전 라인 16-21)에 제안 큐 판정 항목이 애초에 없었다는 것.
   종합자가 매일 실행하는 프롬프트 자체가 이 작업을 요구하지 않았다. 이 공백이 큐 #8(공유
   파일 경합 방지)의 무판정 지속 → 경합 반복(최감사 마찰2·박빌드 마찰3·오운영 마찰1)과 D-0
   콘텐츠 이중 게이트(김기획 마찰2·서카피 마찰1)로 이어졌다.

나머지 항목(QA "부분 통과" 3단계 공식화, PM 배정=채택 확정 규칙, PR 파일접수 표준화, 상시
루틴 배정행, 제안 선언=큐 등록 동시화)은 이번 주 빈도가 1건이거나 아래 두 수정이 선행되면
자연히 완화되는 2차 증상으로 판단해 보류한다(회의 스크립트 지시 — 개정안 최대 2건).

## 결정

### A. 사규 3조 보완 (`org/handbook.md`)
검증 방법 항목 뒤에 문단 추가:
> 검증 방법은 작성자가 확정 전 1회 직접 실행한 결과를 전제로 쓴다. 실행하지 못했으면
> "미실측"이라고 적는다. 실행 주체가 대표 전용 자원(배포·재기동·`!지시` 발신 등)에 의존하면
> 그 사실을 검증 방법 항목에 "대표 발신 전제"로 따로 표시한다.

적용 완료 (본 커밋, `org/handbook.md` 3조).

### B. 스탠드업 종합 스크립트 수정 (`runtime/meeting.mjs`)
`standup.digest` 지시에 항목 추가:
> 5) org/proposals.md에서 금일 기한 도래(판정 기한 ≤ 오늘) 제안을 채택/기각/보류로 판정하고
> 한 줄 사유를 적어라 (해당 없으면 "없음")

적용 완료 (본 커밋, `runtime/meeting.mjs` standup.digest).

## 기대 효과
- A: 지시서 확정 시점에 환경 불일치를 걸러 착수 단계에서의 재발견 비용(관측치: 10일 지연·반나절
  정정)을 제거한다.
- B: 제안 큐 판정이 종합자의 수작업 기억이 아니라 매일 실행되는 프롬프트의 고정 항목이 되어
  48시간 룰이 설계대로 작동한다. 큐 #2·#3·#4·#6·#7·#8·#9·#10(적체 8건)은 다음 스탠드업
  (2026-10-03)부터 자동으로 상정된다.
