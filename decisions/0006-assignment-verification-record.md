# 0006. 배정·검증판정의 정본 단일화
상태: Accepted
날짜: 2026-09-04 확정 (2026-09-08 ADR 전환)
결정자: 한실장 (9/4 스프린트 회고 종합 — 되돌릴 수 있는 사내 절차 사안으로 직접 확정, 대표 승인 불요)

## 맥락
배정이 GitHub 이슈(전원 `담당:없음`)·sprint-01.md 배정표·org/assignments.md 세 곳에 나뉘어
갱신 트리거 없이 사람 손으로 이식됐다. 그 결과 #7은 9/3 검증 합격인데 배정표는 9/4까지
"검증 대기" 오기재 상태였고, 오운영의 중복 확인 작업이 발생했다(2026-09-04-retro.md 종합).
9/4 회고에서 7인 전원이 같은 구조 문제를 지적해 종합에서 확정됐다.

## 결정
1. org/assignments.md 를 배정·상태의 **유일 정본**으로 한다.
2. 검증 판정의 정본은 **산출물 파일 최상단 "검증자/날짜/판정" 1행**이다.
   배정표 상태 열과 회의록은 이것을 인용만 한다.
3. 사규 3조(업무 지시서 규격)에 판정 기록 위치 항목을 한 줄 추가한다.

## 근거
- 대안 1 — sprint-01.md 단일 소스(이빌드 안): 스프린트 마감 시 파일의 역할이 끝나 상시
  배정판으로 부적합.
- 대안 2 — GitHub 이슈 assignee 정복(근본 해법): gh CLI 설치 승인(approvals #3)이 무회신이라
  시점 불확실. 즉시 시행 가능하고 확보 후 이전 가능한 assignments.md 를 채택.
- 검증 판정 위치를 산출물 상단으로 옮기면 판정이 요청자에게 익일 종합까지 못 닿던
  구조(사규 4조는 완료 증명만 정의)가 종료된다.

## 결과
- 매일 배정 근거 파일을 재인용·대조하던 절차 제거(9/2 #8 중복 착수, 9/3·9/4 정합성 지적 방지).
- gh CLI 확보 시 이슈 assignee 로 정본을 이전한다(그때 새 ADR).
- sprint-01.md 배정표와 이슈 `담당:없음` 표기는 정본 아님으로 명시적으로 남는다.
