# 0004. 직원의 도구 경계는 파일과 셸로 한정한다

상태: Accepted
날짜: 2026-08-18
결정자: 대표

## 맥락
직원들에게 도구를 주기 위해 Claude Code CLI 를 통해 실행하도록 바꿨다.
그 직후 김기획이 두레와 무관한 외부 디스코드 서버(대표 개인 계정에 연결돼 있던 곳)에 글을 올렸다.

원인: `claude` CLI 는 기본적으로 사용자 전역 설정의 MCP 서버를 전부 상속한다.
파일·셸만 주려던 의도와 달리, 대표 개인 계정에 붙은 모든 커넥터가 직원에게 딸려갔다.
권한을 넓히면서 경계를 먼저 긋지 않은 설계 실수다.

## 결정
직원이 쓸 수 있는 도구를 **파일 6종과 셸로 고정**한다: Read, Write, Edit, Glob, Grep, Bash.

기술적 강제 (세 겹):
1. `--strict-mcp-config` + 빈 MCP 설정 파일 → 사용자·프로젝트 MCP 전부 무시
2. `--tools Read,Write,Edit,Glob,Grep,Bash` → 내장 도구도 화이트리스트만
3. `CLAUDE_CONFIG_DIR` 을 회사 폴더로 격리 → 대표 개인 스킬·플러그인·설정 차단
   실무진(z.ai)은 `--bare` 추가. 임원진은 OAuth 가 필요해 `--bare` 를 쓸 수 없으므로 1~3 으로 막는다.

규정적 강제: 사규 13조(통신 경계) 신설.

## 원칙 (앞으로 지킬 것)
**권한을 넓힐 때는 경계를 먼저 긋는다.** 도구를 추가하기 전에 그 도구로 갈 수 있는 최대 범위를
먼저 적고, 그 범위를 좁히는 설정을 같은 커밋에 넣는다.

## 결과
- 검증: `#대표실`에서 도구 목록을 물어 6개만 나오는 것을 확인 (2026-08-18)
- 잃은 것: 직원이 외부 서비스를 직접 다룰 수 없다. 필요해지면 그때 개별 승인으로 연다.
- 남은 확인: 사고 당시 노출됐던 커넥터 범위를 대표가 점검할 것
