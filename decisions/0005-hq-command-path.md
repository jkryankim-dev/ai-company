# 0005. 본사 지휘 경로: 대표 → 코워크 본사 → git 지시함 → VPS

상태: Accepted
날짜: 2026-08-18
결정자: 대표

## 맥락
본사가 VPS 로 이전한 뒤 대표는 "디스코드는 읽기만, 지시는 코워크 세션(본사)에" 방식을 택했다.
그러나 코워크 클라우드 샌드박스는 외부망(GitHub push, Discord, z.ai)이 차단되어
본사가 회사에 직접 지시를 넣을 통로가 없었다.

## 결정
git 저장소를 명령 버스로 쓴다.
1. 본사는 대표 PC 의 저장소에 `inbox/pending/*.md` 로 지시 파일을 쓴다 (device bridge).
2. PC 의 "우체부"(start-courier.bat = sync.mjs 단독 실행)가 커밋·푸시한다.
   우체부는 게이트웨이·스케줄러를 띄우지 않으므로 VPS 와 이중 응답 충돌이 없다.
3. VPS 의 sync 가 5분 주기로 pull, inbox 워커가 1분 주기로 pending 을 집어 실행한다.
   한실장이 판단·위임하고, 결과는 디스코드 각 채널과 `inbox/done/` 에 남는다.
4. 런타임 코드가 갱신되면 sync 가 재기동 플래그를 세우고 supervisor 가 스스로 종료,
   systemd 가 새 코드로 되살린다. 이후 배포에 사람 손이 필요 없다.

## 한계
- 본사가 지시를 넣으려면 대표 PC(데스크톱 앱)가 켜져 있어야 한다. 대표가 본사와 대화하는
  시점에는 항상 PC 가 켜져 있으므로 실질 제약이 아니다.
- 지시 전달 지연: 우체부 푸시(즉시) + VPS pull(≤5분) + inbox 스캔(≤1분) ≈ 최대 6분.

## 결과
대표의 조작 채널이 하나로 준다: 코워크에서 말하면 끝. PowerShell·디스코드 타이핑·IDE 경유 불필요.
